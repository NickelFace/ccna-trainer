## Зачем сети рисуют слоями

Плоская сеть из десяти коммутаторов, включённых друг в друга как получилось, работает —
ровно до первого сбоя. Иерархия нужна не ради красоты: она делает так, что **отказ
предсказуем, а рост не требует переделки**. Каждому слою назначена ровно одна работа, и
устройство одного слоя не берёт на себя работу другого.

## Трёхуровневая (three-tier) архитектура

```txt
        [ Core ]  [ Core ]
          |  \      /  |
          |   \    /   |
      [ Dist ]      [ Dist ]
        |    \      /    |
   [Access][Access][Access]
      |       |        |
    PC/AP   PC/AP    PC/AP
```

| Слой | Работа | Чего там не делают |
|---|---|---|
| **Access** | подключение конечных устройств, PoE, VLAN, port security, PortFast | маршрутизации и фильтрации магистрального трафика |
| **Distribution** | агрегирование access-коммутаторов, inter-VLAN routing, ACL и QoS-политики, граница broadcast-доменов | подключения пользователей напрямую |
| **Core** | быстрая коммутация между блоками distribution, максимальная доступность | тяжёлых политик, ACL, NAT — всё, что тормозит |

Правило, которое проверяют вопросами: **политика — на distribution, скорость — на core,
пользователи — на access**. Access-коммутаторы никогда не соединяют друг с другом
напрямую в этой модели; каждый идёт двумя аплинками в два distribution-коммутатора.

## Двухуровневая (collapsed core)

Если площадка одна и блоков distribution всего один-два, отдельный core становится
лишними коробками: distribution и core «схлопывают» в один слой — отсюда название
**collapsed core**.

- Дешевле: меньше устройств, меньше портов, меньше лицензий.
- Логика та же: access внизу, объединённый слой сверху.
- Предел применимости — когда блоков distribution становится больше трёх-четырёх:
  соединять их между собой полной сеткой дороже, чем поставить core.

## Spine-leaf

Классическая иерархия строилась под трафик **north-south** — от пользователя к серверу и
в интернет. В дата-центре трафик стал **east-west**: виртуальные машины и микросервисы
разговаривают между собой куда больше, чем с внешним миром. Дерево с корнем для этого плохо
подходит — путь между двумя серверами может подниматься до core и спускаться обратно.

```txt
   [Spine]   [Spine]   [Spine]
     |  \  /   |  \  /   |
     |   X     |   X     |
   [Leaf]   [Leaf]   [Leaf]
     |         |        |
  серверы   серверы  серверы
```

Свойства, которые спрашивают:

- **Каждый leaf соединён с каждым spine**; leaf с leaf и spine со spine — никогда.
- Путь между любыми двумя серверами всегда одинаковый: leaf → spine → leaf. Отсюда
  предсказуемая задержка (**два хопа всегда**).
- Расширение по полосе — добавить spine; расширение по портам — добавить leaf.
- STP в такой фабрике не используется: работает L3 между leaf и spine (ECMP) либо
  overlay (VXLAN), поэтому все линки активны одновременно.

## Физические топологии

| Топология | Как выглядит | Где встречается |
|---|---|---|
| **Star (звезда)** | все узлы к одному центру | почти любая современная LAN |
| **Full mesh** | каждый с каждым, `n(n−1)/2` линков | ядро WAN, где нужна максимальная отказоустойчивость |
| **Partial mesh** | ключевые узлы связаны напрямую, остальные — нет | типичный WAN-компромисс цена/отказоустойчивость |
| **Hub-and-spoke** | филиалы только с центром | WAN с центральным ЦОД, дёшево, но центр — единая точка отказа |
| **Ring (кольцо)** | по кругу | городские оптические сети, metro Ethernet |
| **Bus (шина)** | общий сегмент | только в истории, коаксиал 10BASE2 |

Число линков для full mesh считают формулой `n(n−1)/2` — вопрос «сколько каналов нужно
для полной сетки из 6 маршрутизаторов» решается в уме: 6·5/2 = 15.

## WAN, SOHO и филиалы

**WAN** соединяет площадки, разнесённые географически, и почти всегда арендуется у
провайдера:

- **Leased line** (выделенная линия) — постоянная точка-точка, своя полоса, дорого.
- **MPLS L3VPN** — провайдер участвует в маршрутизации, площадки видят друг друга как
  соседей.
- **Metro Ethernet** — Ethernet как услуга внутри города.
- **Broadband + VPN over Internet** — дёшево, полоса не гарантирована; поверх него строят
  IPsec-туннели или SD-WAN.
- **Сотовая связь (LTE/5G)** — обычно резерв основного канала.

**SOHO** (small office / home office) — сеть на одно помещение: один комбинированный
роутер с встроенным коммутатором, точкой доступа, DHCP-сервером, NAT и firewall. Всё то
же самое, что в кампусе, но в одной коробке и без резервирования. Экзамен любит
подчёркивать: в SOHO **одно устройство совмещает роли**, а в кампусе роли разнесены.

## On-premise и облако

| | On-premise | Облако |
|---|---|---|
| Где стоит железо | в вашем ЦОД | у провайдера |
| Кто обслуживает | вы | провайдер |
| Оплата | CapEx, покупка вперёд | OpEx, по потреблению |
| Скорость масштабирования | недели (закупка) | минуты |
| Контроль над данными | полный | ограничен договором |

Модели обслуживания:

- **IaaS** — вам дают виртуальную машину и сеть; ОС и всё выше — ваша забота.
- **PaaS** — вам дают среду выполнения; вы приносите только код.
- **SaaS** — вам дают готовое приложение (почта, CRM), вы управляете только учётками.

Модели развёртывания: **public**, **private**, **hybrid** (часть нагрузки внутри, часть
снаружи, между ними защищённый канал), **community**.

> [!key] Запомнить
> Гибридное облако требует связности: либо IPsec/VPN через интернет, либо выделенное
> подключение (Direct Connect / ExpressRoute). Это самый частый «правильный ответ» в
> вопросах про перенос части нагрузки в облако.

## Что спрашивают

- «Which two characteristics describe the access layer in a three-tier architecture?» —
  подключение конечных устройств, PoE, port security; **не** маршрутизация между
  distribution-блоками и не транзит трафика между зданиями.
- «What is the benefit of a collapsed core design?» — меньше устройств и стоимости для
  небольшой площадки при сохранении иерархии.
- «Which topology provides a predictable two-hop path in a data center?» — spine-leaf.
- «How many links are required for a full mesh of N routers?» — `N(N−1)/2`.
- Вопросы про SOHO обычно проверяют, что одно устройство выполняет функции роутера,
  коммутатора, точки доступа и firewall одновременно.
- Про облако чаще всего спрашивают разницу CapEx/OpEx и кто за что отвечает в IaaS/PaaS/SaaS.

## Проверь себя

```check
?? На каком слое трёхуровневой модели применяют ACL и inter-VLAN routing?
!! На distribution. Core оставляют максимально быстрым и без политик.
?? Почему в spine-leaf не нужен STP?
!! Между leaf и spine работает маршрутизация (ECMP) или overlay вроде VXLAN — петель L2 нет, все линки активны.
?? Сколько каналов нужно для полной сетки из 7 площадок?
!! 7·6/2 = 21.
?? Чем collapsed core отличается от three-tier?
!! Слои distribution и core объединены в один — это тот же дизайн для площадки, которой не нужен отдельный core.
?? Компания перенесла часть серверов к провайдеру, остальное осталось в своём ЦОД. Как называется модель и что нужно между частями?
!! Hybrid cloud; нужен защищённый канал — IPsec VPN или выделенное подключение.
```
