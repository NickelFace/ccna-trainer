## Единственное правило

Роутер выбирает маршрут **не** по порядку строк в конфигурации и **не** по тому, кто
пришёл первым. Он выбирает по длине совпадающего префикса — «чем конкретнее, тем лучше».

Пример таблицы:

```cli
S     0.0.0.0/0        via 203.0.113.1
D     10.0.0.0/8       via 10.1.1.2
O     10.1.0.0/16      via 10.1.1.6
S     10.1.5.0/24      via 10.1.1.10
S     10.1.5.64/26     via 10.1.1.14
```

Куда пойдут пакеты:

| Назначение | Выбранный маршрут | Почему |
|---|---|---|
| 10.1.5.70 | `10.1.5.64/26` | самый длинный совпавший префикс |
| 10.1.5.200 | `10.1.5.0/24` | в /26 не входит (там только .64–.127) |
| 10.1.9.4 | `10.1.0.0/16` | не попал ни в один /24 |
| 10.9.0.1 | `10.0.0.0/8` | совпал только /8 |
| 8.8.8.8 | `0.0.0.0/0` | не совпало ничего конкретного |

> [!key] Запомнить
> Административная дистанция и метрика сравниваются **только среди маршрутов с одинаковым
> префиксом**. Сначала выбирается самая точная строка, и лишь потом — из нескольких таких
> строк лучшая по AD и метрике.

## Как проверить себя быстро

Возьми назначение и посчитай, входит ли оно в диапазон каждой строки:

`10.1.5.70` и строка `10.1.5.64/26`: магическое число 64, блок 64–127 → **входит**.
`10.1.5.200` и та же строка: 200 > 127 → **не входит**, спускаемся к /24.

Это ровно арифметика подсетей из первой главы про них — вся сложность вопросов «какой
маршрут выберет роутер» в этом.

## Балансировка equal-cost

Если два маршрута к одной сети имеют **одинаковый префикс, одинаковую AD и одинаковую
метрику**, роутер использует оба (по умолчанию до 4 путей, максимум зависит от платформы):

```cli
R1# show ip route 192.168.9.0
Routing entry for 192.168.9.0/24
  Known via "ospf 1", distance 110, metric 20
  Routing Descriptor Blocks:
  * 10.0.0.2, from 10.0.0.2, via GigabitEthernet0/1
      10.0.0.6, from 10.0.0.6, via GigabitEthernet0/2
```

Балансировка идёт **по потокам** (per-destination) при CEF — это значит, что один и тот же
поток стабильно идёт по одному пути, а разные потоки распределяются. Per-packet тоже
возможна, но вызывает переупорядочивание пакетов и почти не применяется.

EIGRP умеет ещё и **unequal-cost** балансировку через `variance` — единственный IGP с
такой возможностью; это встречается как отличительный факт про EIGRP.

## Рекурсивный поиск next hop

Статический маршрут можно задать тремя способами:

```cfg
ip route 192.168.5.0 255.255.255.0 10.1.1.2                     ! только next hop
ip route 192.168.5.0 255.255.255.0 GigabitEthernet0/1           ! только интерфейс
ip route 192.168.5.0 255.255.255.0 GigabitEthernet0/1 10.1.1.2  ! и то, и другое
```

При задании через next hop роутер обязан **рекурсивно** найти, как добраться до самого
`10.1.1.2` — то есть в таблице должен быть маршрут и до него. Если его нет, маршрут не
установится вовсе (`%Route not installed`). Это причина «прописал маршрут, а его нет в
таблице».

Задание только через интерфейс на многоточечных сетях (Ethernet) плохо работает: роутер
будет слать ARP-запрос на каждый адрес назначения (proxy ARP), что медленно и неочевидно.
Поэтому на Ethernet-линках рекомендуют указывать **интерфейс и next hop вместе**.

## Что происходит с кадром при пересылке

Уже разбиралось в главе про инкапсуляцию, но здесь это причина типовых ошибок:

1. Роутер снимает L2-заголовок.
2. Ищет маршрут по destination IP.
3. Уменьшает TTL, пересчитывает контрольную сумму.
4. Строит **новый** L2-заголовок: source MAC — свой исходящий интерфейс, destination MAC —
   next hop (узнаётся через ARP).
5. Отправляет.

Если ARP до next hop не разрешается (сосед недоступен), маршрут в таблице есть, а трафик
не идёт. `show ip arp` — следующее место после `show ip route`.

## Быстрая пересылка

- **Process switching** — каждый пакет обрабатывает CPU. Медленно, встречается как
  «худший вариант».
- **Fast switching** — первый пакет через CPU, остальные по кэшу.
- **CEF** (Cisco Express Forwarding) — заранее построенные FIB и таблица смежностей;
  включён по умолчанию, работает на скорости порта.

```cli
R1# show ip cef 192.168.5.10
192.168.5.0/24
  nexthop 10.1.1.2 GigabitEthernet0/1
```

## Что спрашивают

- «Which route does the router use to forward the packet?» — longest prefix match.
- «How does the router load balance across two equal paths?» — по потокам, при равных
  AD и метрике.
- «Why is the configured static route missing from the routing table?» — нет маршрута до
  next hop (рекурсия не разрешилась) или интерфейс down.
- «Which protocol supports unequal-cost load balancing?» — EIGRP (variance).
- «What does the router rewrite when forwarding?» — MAC-адреса и TTL, IP не трогает.
