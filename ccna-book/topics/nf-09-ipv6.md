## Как читается адрес

128 бит, восемь групп по 16 бит в шестнадцатеричном виде, разделённых двоеточиями:

```txt
2001:0db8:0000:0000:0000:ff00:0042:8329
```

Два правила сокращения:

1. **Ведущие нули в группе отбрасываются**: `0db8` → `db8`, `0000` → `0`.
2. **Одна** самая длинная цепочка групп из нулей заменяется на `::` — ровно один раз за
   адрес, иначе восстановить длину невозможно.

```txt
2001:db8::ff00:42:8329
```

Обратная задача — «развернуть» адрес — тоже спрашивают: `2001:db8::1` это
`2001:0db8:0000:0000:0000:0000:0000:0001`.

> [!trap] Ловушка
> `2001:db8::ab::1` — неверный адрес: два `::` в одной записи запрещены. Такой вариант
> регулярно подкладывают в ответы.

## Структура global unicast

```txt
 2001:0db8:aaaa : bbbb : узел........................
 └── глобальный префикс ─┘ └ subnet ┘ └ interface ID ┘
        /48                  /64            64 бита
```

- Глобальные адреса выданы из `2000::/3` (то есть начинаются с 2 или 3).
- Стандартная длина подсети — **/64**, и почти всё в IPv6 на неё рассчитано (SLAAC не
  работает при другой длине).
- Провайдер обычно выдаёт организации /48, из него нарезают /64 на каждую VLAN.

## Типы адресов

| Тип | Префикс | Смысл |
|---|---|---|
| Global unicast | 2000::/3 | маршрутизируемый в интернете |
| Unique local (ULA) | FC00::/7 (практически FD00::/8) | «частный» аналог RFC 1918, наружу не маршрутизируется |
| Link-local | FE80::/10 | обязателен на каждом интерфейсе, живёт только в пределах канала |
| Multicast | FF00::/8 | группа получателей |
| Anycast | из обычного unicast-диапазона | адрес, назначенный нескольким узлам; доставка ближайшему |
| Loopback | ::1 | сам узел |
| Unspecified | :: | «адреса нет», источник при автонастройке |

**Broadcast в IPv6 отсутствует** — это самый частый правильный ответ в вопросах «что верно
про IPv6».

### Link-local — не декорация

Адрес `FE80::/10` появляется на интерфейсе автоматически, как только включён IPv6. На нём
держится всё соседское взаимодействие: NDP, объявления роутера, а также **соседство OSPFv3
и EIGRPv6** и next-hop в таблице маршрутизации. Пакет с link-local источником никогда не
уходит за пределы канала.

## Multicast-группы, которые надо узнавать

| Адрес | Кто слушает |
|---|---|
| FF02::1 | все узлы на канале (аналог broadcast) |
| FF02::2 | все роутеры на канале |
| FF02::5 / FF02::6 | OSPFv3: все роутеры / DR и BDR |
| FF02::9 | RIPng |
| FF02::A | EIGRPv6 |
| FF02::1:FFxx:xxxx | solicited-node — используется в NDP вместо ARP |

Первые две спрашивают чаще всего: `ping FF02::1` — способ увидеть соседей на канале.

## Как узел получает адрес

1. **Статически** — как в IPv4, руками.
2. **SLAAC** (stateless autoconfiguration) — узел слышит Router Advertisement, берёт из
   него префикс /64 и **сам придумывает** себе интерфейсную часть: либо по EUI-64, либо
   случайную (privacy extensions). Сервер не нужен, но и DNS оттуда не приходит (для этого
   есть stateless DHCPv6).
3. **DHCPv6 stateful** — сервер выдаёт адрес и параметры, как в IPv4.

Обязательная часть любого способа — **DAD** (duplicate address detection): прежде чем
использовать адрес, узел спрашивает через NDP, не занят ли он.

### EUI-64 руками

Из MAC `00:1A:2B:3C:4D:5E` получить интерфейсный идентификатор:

1. Разбить пополам и вставить в середину `FFFE`:
   `001A:2BFF:FE3C:4D5E`.
2. **Инвертировать седьмой бит** первого байта (бит U/L): `00` = 00000000 → 00000010 =
   `02`.
3. Итог: `021A:2BFF:FE3C:4D5E`, а полный адрес с префиксом — `2001:db8:1:1:21a:2bff:fe3c:4d5e`.

Признак EUI-64 в готовом адресе — `FF:FE` в середине интерфейсной части. Это и есть
подсказка к вопросам «какой адрес сформирован по EUI-64».

## Вместо ARP — NDP

| Задача | IPv4 | IPv6 |
|---|---|---|
| Узнать MAC соседа | ARP request/reply | Neighbor Solicitation / Advertisement |
| Найти роутер | DHCP или статика | Router Solicitation / Advertisement |
| Проверить дубликат адреса | gratuitous ARP | DAD (NS на собственный адрес) |
| Перенаправление | ICMP redirect | ICMPv6 redirect |

Всё это — сообщения **ICMPv6**, поэтому «просто заблокировать ICMPv6» в IPv6-сети означает
сломать её работу; в вопросах про безопасность это встречается.

## Настройка на Cisco

```cfg
ipv6 unicast-routing
!
interface GigabitEthernet0/0
 ipv6 address 2001:db8:acad:1::1/64
 ipv6 address fe80::1 link-local
!
interface GigabitEthernet0/1
 ipv6 address 2001:db8:acad:2::/64 eui-64
```

```cli
R1# show ipv6 interface brief
GigabitEthernet0/0     [up/up]
    FE80::1
    2001:DB8:ACAD:1::1
R1# show ipv6 neighbors
IPv6 Address        Age Link-layer Addr State Interface
2001:DB8:ACAD:1::10   0 0050.7966.6800  REACH Gi0/0
```

Без `ipv6 unicast-routing` устройство работает как хост: адреса есть, маршрутизации и
Router Advertisement нет — частая причина «клиенты не получают SLAAC».

## Сосуществование с IPv4

- **Dual stack** — оба протокола одновременно на одном интерфейсе; предпочтительный и
  самый простой путь миграции.
- **Туннелирование** (6in4, GRE, 6to4) — IPv6 внутри IPv4 через сеть, которая IPv6 не
  умеет.
- **Трансляция** (NAT64) — общение IPv6-узла с IPv4-ресурсом.

## Что спрашивают

- «Which IPv6 address is the correct abbreviation of…» — правила сокращения.
- «What is the purpose of the FE80::/10 address?» — связь в пределах канала, соседство
  протоколов, next-hop.
- «Which multicast address do all routers listen to?» — FF02::2.
- «Which address was generated using EUI-64?» — по FF:FE в середине.
- «What are two characteristics of IPv6?» — нет broadcast, адрес 128 бит, нет
  фрагментации на промежуточных роутерах, встроенный NDP.
- Drag-and-drop: сопоставить префикс с типом адреса (2000::/3, FE80::/10, FC00::/7,
  FF00::/8).
