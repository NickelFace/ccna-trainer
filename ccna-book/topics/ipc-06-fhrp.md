## Задача

У хоста один шлюз по умолчанию, и он прописан статически или выдан по DHCP. Если роутер с
этим адресом умрёт, вся подсеть останется без выхода — даже когда рядом стоит второй,
полностью рабочий роутер.

**FHRP** решает это виртуальным адресом: два (или больше) роутера делят один **виртуальный
IP** и один **виртуальный MAC**. Хосты знают только их, а кто именно отвечает — их не
касается.

```txt
            10.1.1.254  (виртуальный IP)
        ┌──────────┴──────────┐
   R1 .1 (active)        R2 .2 (standby)
        └────────┬────────────┘
              PC gw = 10.1.1.254
```

## Три протокола

| | HSRP | VRRP | GLBP |
|---|---|---|---|
| Происхождение | Cisco | открытый (RFC 5798) | Cisco |
| Роли | Active / Standby | Master / Backup | AVG + до 4 AVF |
| Балансировка нагрузки | нет (только по разным VLAN) | нет | **да, встроенная** |
| Приоритет по умолчанию | 100 | 100 | 100 |
| Кто выигрывает | больший приоритет, затем больший IP | так же | так же |
| Виртуальный MAC | 0000.0C07.ACxx | 0000.5E00.01xx | 0007.B400.xxxx |
| Multicast | 224.0.0.2 (v1) / 224.0.0.102 (v2) | 224.0.0.18 | 224.0.0.102 |
| Таймеры по умолчанию | hello 3 с, hold 10 с | advert 1 с | hello 3 с |

**GLBP** отличается принципиально: он раздаёт **разные виртуальные MAC разным хостам** в
ответ на ARP, поэтому трафик подсети распределяется между всеми роутерами группы. У HSRP и
VRRP трафик всегда идёт через одного, а балансировку изображают вручную, делая один роутер
активным для VLAN 10, а другой — для VLAN 20.

## Настройка HSRP

```cfg
interface Vlan10
 ip address 10.1.1.1 255.255.255.0
 standby version 2
 standby 10 ip 10.1.1.254
 standby 10 priority 110
 standby 10 preempt
 standby 10 track GigabitEthernet0/1 20
```

Разбор:

- `standby 10` — номер группы; он же попадает в виртуальный MAC и должен совпадать на
  обоих роутерах.
- `priority 110` — больше, чем 100 по умолчанию, значит этот роутер хочет быть активным.
- **`preempt`** — без него роутер с лучшим приоритетом **не отберёт** роль у уже активного
  после возврата из перезагрузки. Это самый частый вопрос по теме: «настроил приоритет, а
  активным остался другой» → не хватает preempt.
- `track` — снижает приоритет на 20, если указанный интерфейс (обычно аплинк) упал: иначе
  роутер остался бы активным, потеряв путь наружу.

VRRP настраивается почти так же (`vrrp 10 ip …`, `vrrp 10 priority …`), но **preempt в
VRRP включён по умолчанию** — ещё одно отличие, которое любят.

## Что ломается

| Симптом | Причина |
|---|---|
| Оба роутера Active | не видят друг друга: разные VLAN, разные группы, ACL режет multicast |
| Роль не переходит обратно | нет `preempt` |
| Активен роутер с упавшим аплинком | не настроен `track` |
| Хосты не видят шлюз | виртуальный IP из другой подсети либо группа задана не на всех |
| Соседство не поднялось | разные версии HSRP (v1 и v2 несовместимы) |

## Что спрашивают

- «Which protocol is an open standard FHRP?» — VRRP.
- «Which FHRP provides load balancing natively?» — GLBP.
- «What is the purpose of the preempt command?» — вернуть роль активного роутеру с
  бо́льшим приоритетом.
- «Which router becomes active?» — с наибольшим приоритетом, при равенстве — с
  наибольшим IP.
- «What is the virtual MAC of HSRP group 10?» — 0000.0C07.AC0A (номер группы в hex).
- «Why did the router remain active after its uplink failed?» — не настроен tracking.

## Проверь себя

```check
?? Роутеру задан приоритет 120, но активным остался сосед с 100. Почему?
!! Не включён preempt — роль не отбирается у уже активного.
?? Какой FHRP умеет распределять трафик подсети между роутерами сам?
!! GLBP: он раздаёт разным хостам разные виртуальные MAC.
?? Что видит хост в качестве шлюза при работе HSRP?
!! Виртуальный IP и виртуальный MAC группы; какой роутер за ними стоит, ему неизвестно.
?? Зачем нужен tracking интерфейса?
!! Чтобы роутер уступил роль активного, если потерял аплинк наружу, а не держал трафик у себя.
?? Чем отличается поведение preempt в VRRP?
!! Там он включён по умолчанию, в HSRP — нет.
```
