## Зачем QoS

Полоса не бесконечна, а трафик неоднороден: копирование резервной копии и телефонный
разговор конкурируют за одну очередь. QoS не создаёт полосу — он **решает, кого
обслуживать первым, когда её не хватает**.

Требования, которые надо помнить наизусть (голос, односторонняя передача):

| Параметр | Голос | Видео |
|---|---|---|
| Задержка (latency) | ≤ 150 мс | ≤ 200–400 мс |
| Джиттер | ≤ 30 мс | ≤ 30–50 мс |
| Потери | ≤ 1 % | ≤ 0,1–1 % |
| Полоса на звонок | 21–320 кбит/с в зависимости от кодека | зависит от разрешения |

## Модели обслуживания

- **Best effort** — QoS нет, все равны. По умолчанию.
- **IntServ** — резервирование ресурсов под поток (RSVP), плохо масштабируется.
- **DiffServ** — трафик делится на классы, каждый узел применяет к классу своё поведение.
  Это и есть **per-hop behavior**, и именно DiffServ используется на практике.

> [!key] Запомнить
> **PHB — поведение на каждом узле.** QoS не сквозной механизм: каждое устройство по пути
> само решает, что делать с помеченным пакетом. Если по дороге хотя бы один узел
> маркировку игнорирует, гарантий нет.

## Классификация и маркировка

**Классификация** — определить, к какому классу относится пакет (по ACL, по порту, по
протоколу через NBAR). **Маркировка** — записать это в заголовок, чтобы следующие узлы не
разбирали пакет заново.

| Поле | Где | Разрядность | Значения |
|---|---|---|---|
| **CoS** | тег 802.1Q, только на транке L2 | 3 бита | 0–7 |
| **DSCP** | байт ToS в заголовке IP | 6 бит | 0–63 |
| IP Precedence | старые 3 бита того же байта | 3 бита | 0–7 |

Ключевые значения DSCP:

| Имя | DSCP | Для чего |
|---|---:|---|
| **EF** (Expedited Forwarding) | 46 | голос |
| AF41 | 34 | видеоконференция |
| AF31 | 26 | сигнализация вызовов |
| AF21 | 18 | транзакционные данные |
| CS0 / default | 0 | всё остальное |

В именах AFxy первая цифра — класс (чем больше, тем выше приоритет), вторая — вероятность
отбрасывания при перегрузке (чем больше, тем скорее отбросят).

CoS живёт только внутри тега VLAN, поэтому **на access-порту без тега его нет** — при
выходе за пределы L2 маркировка должна быть в DSCP.

## Граница доверия

**Trust boundary** — место, где сеть начинает верить чужой маркировке. Правило: доверять
как можно ближе к источнику, но только тому, кому можно.

- IP-телефон Cisco — доверенное устройство: `mls qos trust cos` на порту.
- Порт обычного ПК — не доверять: пользователь может пометить торренты как EF и получить
  приоритет. Маркировку с такого порта либо обнуляют, либо перезаписывают по политике.

## Управление очередями

- **Congestion management** — что делать, когда очередь заполнена: несколько очередей и
  порядок их обслуживания.
  - **CBWFQ** — гарантированная доля полосы каждому классу.
  - **LLQ** — приоритетная очередь поверх CBWFQ; **обязательна для голоса**, потому что
    только она даёт предсказуемо низкую задержку.
- **Congestion avoidance** — не доводить до переполнения: **WRED** заранее отбрасывает
  часть пакетов менее важных классов, чтобы TCP-сессии сами снизили скорость. Без этого
  случается **tail drop** — при переполнении отбрасывается всё подряд, включая голос.

## Policing и shaping

| | Policing | Shaping |
|---|---|---|
| Что делает с превышением | **отбрасывает** (или перемаркирует) | **буферизует** и выпускает позже |
| Влияние на задержку | нет | увеличивает |
| Где применяют | на входе, у провайдера | на выходе, к каналу провайдера |
| Форма трафика | резкая, всплески срезаются | сглаженная |

Мнемоника: **police = штраф на месте (drop), shape = очередь и выпуск по расписанию.**
Для TCP shaping обычно мягче: вместо потерь и повторных передач — небольшая задержка.

## Как это выглядит в конфигурации

```cfg
class-map match-all VOICE
 match ip dscp ef
class-map match-all SIGNALING
 match ip dscp af31
!
policy-map WAN-OUT
 class VOICE
  priority percent 10               ! LLQ — строгий приоритет
 class SIGNALING
  bandwidth percent 5
 class class-default
  fair-queue
  random-detect                     ! WRED
!
interface GigabitEthernet0/0
 service-policy output WAN-OUT
```

## Что спрашивают

- «Which DSCP value is used for voice?» — EF, 46.
- «What is the difference between policing and shaping?» — отбрасывает против
  буферизует.
- «What is a trust boundary?» — граница, где принимается чужая маркировка.
- «Which queuing method should be used for voice?» — LLQ (priority queue).
- «What are the latency/jitter/loss requirements for voice?» — 150 мс / 30 мс / 1 %.
- «Where does CoS marking exist?» — в теге 802.1Q, то есть только на транке.
- «What does per-hop behavior mean?» — каждое устройство по пути применяет политику
  самостоятельно.

```check
?? Где правильно ставить границу доверия для IP-телефона и для ПК?
!! Телефону доверять (trust cos), маркировку с порта обычного ПК — не принимать.

```
