## Когда статика уместна

Протокол маршрутизации нужен там, где сеть меняется. Если сеть маленькая и стабильная,
статические маршруты дешевле: нет обмена служебным трафиком, нет соседств, поведение
полностью предсказуемо.

Типичные случаи:

- **Тупиковая сеть (stub)** — филиал с единственным выходом: ему хватает маршрута по
  умолчанию.
- **Маршрут по умолчанию к провайдеру** — самый частый статический маршрут вообще.
- **Резервный путь** (floating static) на случай отказа основного.
- Точечное исправление там, где протокол даёт не тот путь.

Минусы столь же очевидны: при изменении топологии никто ничего не пересчитает, а в большой
сети число записей растёт квадратично.

## Синтаксис IPv4

```cfg
! сетевой маршрут через next hop
ip route 192.168.5.0 255.255.255.0 10.1.1.2

! через исходящий интерфейс
ip route 192.168.5.0 255.255.255.0 GigabitEthernet0/1

! рекомендуемая форма на Ethernet: интерфейс + next hop
ip route 192.168.5.0 255.255.255.0 GigabitEthernet0/1 10.1.1.2

! маршрут по умолчанию
ip route 0.0.0.0 0.0.0.0 203.0.113.1

! хостовый маршрут (/32) — только к одному адресу
ip route 10.9.9.9 255.255.255.255 10.1.1.2

! floating static: AD 5 вместо 1 — включится, когда пропадёт основной
ip route 192.168.5.0 255.255.255.0 10.1.1.6 5
```

Последнее число в строке — **административная дистанция**. По умолчанию у статики она 1,
поэтому статический маршрут выигрывает почти у любого протокола. Именно это и превращают в
floating static: задают AD выше, чем у динамического источника (например, 130 при OSPF
110), и маршрут спокойно ждёт своей очереди.

> [!key] Запомнить
> **Floating static** = статический маршрут с увеличенной AD. Он не появится в таблице,
> пока жив основной маршрут, и подхватит трафик при его исчезновении. В выводе `show ip
> route` его не видно — это нормально, смотри `show ip route <сеть>` или конфигурацию.

## Синтаксис IPv6

```cfg
ipv6 unicast-routing
!
ipv6 route 2001:db8:acad:5::/64 2001:db8:acad:1::2
ipv6 route ::/0 GigabitEthernet0/0 fe80::2        ! дефолт через link-local
ipv6 route 2001:db8:acad:9::1/128 2001:db8:acad:1::2
```

Отличие, которое спрашивают: если next hop задан **link-local адресом**, обязательно
указывать и исходящий интерфейс — link-local адрес не уникален в пределах роутера, и без
интерфейса непонятно, куда слать.

## Проверка

```cli
R1# show ip route static
S     192.168.5.0/24 [1/0] via 10.1.1.2
S*    0.0.0.0/0 [1/0] via 203.0.113.1

R1# show ipv6 route static
S   2001:DB8:ACAD:5::/64 [1/0]
     via 2001:DB8:ACAD:1::2

R1# show ip route 192.168.5.10
Routing entry for 192.168.5.0/24
  Known via "static", distance 1, metric 0
```

## Почему маршрут не работает

| Симптом | Причина |
|---|---|
| Маршрута нет в таблице | интерфейс next hop down; нет маршрута до next hop (рекурсия); опечатка в маске |
| Маршрут есть, трафик не идёт | нет обратного маршрута на дальней стороне |
| Работает в одну сторону | классика: на удалённом роутере нет пути назад |
| Пропал при отказе линка | так и задумано: маршрут через down-интерфейс снимается |
| Резервный не включился | AD резервного не выше основного, либо основной формально «жив» |

**Обратный маршрут** — причина номер один в задачах на troubleshooting. Ping не проходит не
потому, что запрос не дошёл, а потому, что ответу некуда возвращаться. Проверяется это
пингом с обеих сторон и `show ip route` на обоих концах.

## Суммарный маршрут вместо десяти

Вместо десяти строк к 10.1.0.0/24 … 10.1.7.0/24 пишут одну:

```cfg
ip route 10.1.0.0 255.255.248.0 10.0.0.2      ! /21 покрывает восемь сетей
```

Так же строят и «маршрут в никуда» для защиты от петель — `ip route 10.1.0.0 255.255.248.0
null0`: всё, что не покрыто конкретными маршрутами, отбрасывается локально, а не гуляет
кругами.

## Что спрашивают

- «Which command configures a default route?» — `ip route 0.0.0.0 0.0.0.0 <next hop>`.
- «What is a floating static route used for?» — резерв на случай отказа основного пути.
- «Which static route is a host route?» — с маской /32 (255.255.255.255).
- «Why is the static route not in the routing table?» — интерфейс down или next hop
  недостижим.
- «Which command adds a backup route with AD 5?» — та же строка с цифрой 5 в конце.
- «What must be configured for an IPv6 static route via a link-local next hop?» — вместе с
  адресом указать выходной интерфейс.

## Проверь себя

```check
?? Как записать маршрут по умолчанию для IPv6?
!! ipv6 route ::/0 <next hop> (с интерфейсом, если next hop link-local).
?? Основной путь идёт по OSPF (AD 110). Какую AD дать резервной статике?
!! Больше 110 — например, 130; иначе статика вытеснит рабочий маршрут OSPF.
?? Ping из сети A в сеть B не проходит, маршрут A→B настроен и виден. Что проверить?
!! Обратный маршрут B→A на дальнем роутере.
?? Чем отличается ip route … Gi0/1 от ip route … 10.1.1.2 на Ethernet-линке?
!! Через интерфейс роутер полагается на proxy ARP для каждого адреса назначения; надёжнее указать next hop (или оба сразу).
?? Что делает маршрут в null0?
!! Отбрасывает пакеты к покрытому диапазону локально — так гасят петли и «дыры» в суммаризации.
```
