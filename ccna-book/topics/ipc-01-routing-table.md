## Что такое таблица маршрутизации

Это список известных роутеру сетей и способ до каждой добраться. Всё, что роутер делает с
пакетом, — ищет в этой таблице **самый длинный совпадающий префикс** и отправляет пакет
next hop-у.

```cli
R1# show ip route
Codes: L - local, C - connected, S - static, R - RIP, M - mobile, B - BGP
       D - EIGRP, EX - EIGRP external, O - OSPF, IA - OSPF inter area
       * - candidate default

Gateway of last resort is 10.10.10.18 to network 0.0.0.0

S*    0.0.0.0/0 [1/0] via 10.10.10.18
      10.0.0.0/8 is variably subnetted, 5 subnets, 3 masks
C        10.10.10.0/30 is directly connected, FastEthernet0/1
L        10.10.10.2/32 is directly connected, FastEthernet0/1
O        10.10.13.0/25 [110/6576] via 10.10.10.1, 06:58:21, FastEthernet0/1
D        10.10.20.0/24 [90/2172416] via 10.10.10.1, 00:12:03, FastEthernet0/1
S        192.168.5.0/24 [1/0] via 10.10.10.6
```

Разбор строки `O 10.10.13.0/25 [110/6576] via 10.10.10.1, 06:58:21, FastEthernet0/1`:

| Часть | Что означает |
|---|---|
| `O` | источник маршрута — OSPF |
| `10.10.13.0/25` | сеть и её префикс |
| `110` | **административная дистанция** |
| `6576` | **метрика** протокола |
| `via 10.10.10.1` | next hop |
| `06:58:21` | сколько маршрут живёт в таблице |
| `FastEthernet0/1` | исходящий интерфейс |

## Коды источников

| Код | Источник |
|---|---|
| `C` | connected — сеть на поднятом интерфейсе |
| `L` | local — /32 адрес самого интерфейса |
| `S` | static |
| `S*` | static default route |
| `O`, `IA`, `E1/E2` | OSPF: внутризонный, межзонный, внешний |
| `D`, `EX` | EIGRP: внутренний, внешний |
| `R` | RIP |
| `B` | BGP |

**C и L появляются парой**: `C` — вся подсеть интерфейса, `L` — сам адрес интерфейса
как /32. Условие появления обоих: интерфейс в состоянии up/up **и** у него есть адрес.
Погас интерфейс — обе записи исчезли, а вместе с ними и всё, что через него шло.

## Административная дистанция: чему верить

AD — «доверие к источнику». Если один и тот же префикс пришёл от двух протоколов, в
таблицу попадёт маршрут с **меньшей AD**.

| Источник | AD |
|---|---:|
| Connected | 0 |
| Static | 1 |
| eBGP | 20 |
| EIGRP (internal) | 90 |
| OSPF | 110 |
| IS-IS | 115 |
| RIP | 120 |
| EIGRP (external) | 170 |
| iBGP | 200 |
| Unusable (маршрут не будет использован) | 255 |

Эту таблицу спрашивают в лоб, а также косвенно: «маршрут пришёл и по OSPF, и по EIGRP —
какой попадёт в таблицу» → EIGRP (90 < 110).

## Метрика: выбор внутри одного протокола

Метрика сравнивается **только между маршрутами одного протокола**:

| Протокол | Метрика |
|---|---|
| RIP | число хопов |
| OSPF | стоимость (cost), обратно пропорциональна полосе |
| EIGRP | композитная: полоса и задержка (по умолчанию) |
| BGP | не метрика, а набор атрибутов (AS-path и другие) |

Сравнивать метрику OSPF с метрикой EIGRP бессмысленно — они в разных единицах, для этого и
существует AD.

## Порядок выбора маршрута

Когда пакет приходит, роутер выбирает так:

1. **Самый длинный совпадающий префикс** — это главный и первый критерий. Маршрут /32
   всегда победит /24, даже если у /24 меньше AD.
2. Если префикс одинаковый — **меньшая AD**.
3. Если и AD одинаковая (один протокол) — **меньшая метрика**.
4. Если всё одинаково — балансировка **equal-cost**, до 4 путей по умолчанию.

> [!key] Запомнить
> Порядок именно такой: **префикс → AD → метрика**. Вопрос «пакет к 10.1.1.5, в таблице
> есть 10.0.0.0/8 по EIGRP и 10.1.1.0/24 по RIP — куда пойдёт» решается на первом шаге:
> по /24, несмотря на худшую AD у RIP.

## Gateway of last resort

Маршрут по умолчанию `0.0.0.0/0` — «всё остальное туда». В выводе он отмечен как
`S*` (статический кандидат) или приходит от протокола маршрутизации. Строка `Gateway of
last resort is …` вверху вывода — то, что читают в первую очередь в вопросах «куда уйдёт
пакет к неизвестной сети».

Если её нет (`Gateway of last resort is not set`), пакет к неизвестной сети **просто
отбрасывается**, а отправителю уходит ICMP Destination Unreachable.

## Типы маршрутов по назначению

- **Network route** — обычная сеть с маской короче /32 (`10.1.1.0/24`).
- **Host route** — `/32`, ровно один адрес. Появляется как `L` для своих интерфейсов, а
  также при явной настройке или от протоколов (например, loopback соседа).
- **Default route** — `0.0.0.0/0`.
- **Floating static** — статический маршрут с искусственно повышенной AD, чтобы он ждал
  в стороне и включался только при отказе основного.

## Полезные команды

```cli
R1# show ip route 10.10.13.7          ! какой маршрут выберется именно для этого адреса
Routing entry for 10.10.13.0/25
  Known via "ospf 1", distance 110, metric 6576

R1# show ip route ospf                ! только маршруты одного протокола
R1# show ip route | include 192.168    ! фильтр по строке
R1# show ip cef 10.10.13.7            ! что реально в таблице пересылки
```

`show ip route <адрес>` — самый прямой способ ответить на вопрос «через что пойдёт пакет»:
роутер сам выполняет longest prefix match.

## Что спрашивают

- «Which route will be used to reach host X?» — longest prefix match по выводу.
- «What is the administrative distance of OSPF / EIGRP / static?» — 110 / 90 / 1.
- «Which two values are shown in brackets?» — AD и метрика.
- «What does the L entry represent?» — локальный /32 адрес интерфейса.
- «Which type of route does R1 use to reach host 10.10.13.10/32?» — по префиксу в выводе:
  если совпал /25, это network route, а не host route.
- «What happens if there is no default route and the destination is unknown?» — пакет
  отбрасывается, отправителю уходит ICMP unreachable.
