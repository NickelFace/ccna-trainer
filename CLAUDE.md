# CCNA-trainer — инструкция проекта

Проект: офлайн-тренажер экзамена Cisco CCNA 200-301. Статические файлы, без бэкенда.
Отделён от подготовки к экзамену (`../CCNA`) — здесь только тренажер и его данные.

## Структура

- `ccna-exam-simulator/` — рабочее приложение
  - `index.html`, `assets/js/app.js`, `assets/css/styles.css` — весь фронтенд
  - `data/questions.json` — банк 1395 вопросов; `data/meta.json` — домены и веса
  - `images/topo/` — 211 SVG-топологий; `images/exhibits/` — 21 растровый экспонат
  - `build/` — пайплайн сборки данных и все override-файлы
  - `README.md` / `README.ru.md` — описание приложения
- `diagrams/` — утверждённый стиль SVG «dark terminal»
  - `diagram-style-prompt.md` — полная спецификация (палитра, иконки, чек-лист)
  - `*.svg` — иконки устройств; эталон раскладки — `demo-topology.svg`
- Архив исходников (PDF-дамп 774 стр., аудит ключа, промежуточные данные):
  `ccna-project-archive/` в корне проекта (298 МБ, см. его README)

## Формат вопроса (data/questions.json)

Поля: `n` номер, `t` текст, `o` варианты, `a` ключ, `y` тип (`txt`/`ex`/`dd`),
`tp` авторская тема, `dom` официальный домен (NF/NA/IPC/IPS/SEC/AUT),
`cli` вывод CLI текстом, `svg`/`img` имя файла экспоната, `dd` данные drag-and-drop,
`why` объяснение по каждому варианту, `exp` подробное объяснение, `disp` спорный ключ.

## Правки данных

- Вопросы НЕ править напрямую в `data/questions.json` — только через override-файлы
  в `build/` (`option_fix.json`, `text_overrides.json`, `classify_overrides.json`,
  `why_data.json`, `dd_data.json`, `exhibit_data.json`, `svg_data.json` и т.п.),
  затем пересборка:
  ```bash
  cd ccna-exam-simulator/build && python3 build_data.py
  ```
- Классификация доменов — своя (по blueprint v1.1, `build/blueprint_domains.md`),
  авторским тегам `tp` из дампа не доверять.

## Запуск

```bash
python3 -m http.server 8099 --directory ccna-exam-simulator
# http://localhost:8099
```

## Стиль диаграмм

Любые новые/перерисованные схемы — строго по `diagrams/diagram-style-prompt.md`:
готовые `<symbol>`, палитра «цвет = тип устройства», чек-лист самопроверки в конце
файла обязателен. Не импровизировать с палитрой и формой иконок.

## Правила работы

1. Сначала рассуждение вслух и интерпретации задачи, потом код.
2. Минимально простой код, без спекулятивной функциональности.
3. Менять только то, о чём явно попросили.
4. Перед задачей сформулировать критерии успеха; проверять каждый шаг.
5. После правок данных — пересборка build_data.py и ручная проверка в браузере.
6. Текущее состояние и открытые вопросы — в `MEMORY.md`; обновлять после значимых сессий.
