# Задача для отдельного чата: поднять аккаунт-часть sync.maks.top

Создано 2026-08-24. Репозиторий: `NickelFace/ccna-trainer`, каталог `ccna-sync/`.
Этот файл самодостаточен — контекст предыдущего чата пересобирать не нужно.

**Кому:** агенту в новом чате Cowork, у которого есть расширение Claude in Chrome.
Работа в браузере: дашборд Cloudflare и настройки GitHub. Код писать не нужно — он готов,
протестирован и лежит в репозитории. Нужны только те шаги, которые физически нельзя
сделать без доступа к аккаунту пользователя.

---

## 0. Правила, которые важнее задачи

- **Пароли, 2FA-коды, вход в аккаунт — только руками пользователя.** Агент не вводит
  учётные данные, не создаёт аккаунты, не проходит CAPTCHA. Если страница просит логин —
  сказать об этом и ждать.
- **API-токен Cloudflare показывается один раз.** Пользователь копирует его сам и сам
  вставляет в поле GitHub secret. **Не просить прислать токен в чат** и не выводить его в
  терминал/лог — он даёт право деплоить воркеры в аккаунте.
- Перед любым необратимым действием (создать токен, добавить секрет, привязать домен) —
  показать, что именно будет сделано, и дождаться «да».
- `database_id` из D1 — **не секрет**, он лежит в репозитории открыто, его можно и нужно
  прислать в чат. Секретны только API-токен и (условно) Account ID.

## 1. Что уже сделано и работает (проверено, не по памяти)

Сервер синхронизации написан целиком и проверен локально.

| файл | что это |
|---|---|
| `ccna-sync/src/worker.js` | весь сервер: `GET /v1/health`, `GET /v1/state`, `PUT /v1/state` |
| `ccna-sync/migrations/0001_state.sql` | таблица `state(key_hash, rev, blob, updated_at)` |
| `ccna-sync/wrangler.jsonc` | конфиг: имя `ccna-sync`, домен `sync.maks.top`, привязка D1 `DB` |
| `ccna-sync/test/worker.test.js` | 13 тестов поверх настоящего SQLite (`node:sqlite`) |
| `ccna-sync/README.md` | протокол и команды |
| `.github/workflows/sync-deploy.yml` | тесты всегда, деплой — когда появятся секреты |

Проверено на этой машине:

- `npm test` — 13/13 зелёных (проверяется настоящий SQL, а не заглушка);
- `npx wrangler d1 migrations apply ccna-sync --local` — миграция применяется;
- `npx wrangler dev` + curl — на реальном runtime (workerd) и реальной локальной D1:
  пустое состояние → `{"rev":0,"blob":null}`, создание → `{"rev":1}`, обновление →
  `{"rev":2}`, устаревший `rev` → `409` с текущим состоянием, без ключа → `401`,
  preflight для `https://ccna.maks.top` разрешён, для чужого origin — нет.

**Единственное, чего не хватает для боевого запуска, — четыре вещи из аккаунта:**
`database_id`, Account ID, API-токен и привязанный домен. Это и есть задача.

### Протокол (чтобы понимать, что проверяем в конце)

```
GET  /v1/health                       → 200 {"ok":true}
GET  /v1/state                        → 200 {"rev":N,"blob":"…"}   (rev 0 / null, если пусто)
PUT  /v1/state {"rev":N,"blob":"…"}   → 200 {"rev":N+1}
                                      → 409 {"rev":M,"blob":"…"}   (кто-то записал раньше)
```

Авторизация — `Authorization: Bearer <sync key>`, длинная случайная строка, которую
пользователь генерирует на одном устройстве и вводит на другом. В базе хранится только
её SHA-256. Аккаунтов и паролей у сервиса нет. Сервер **не разбирает** blob — все правила
слияния живут в клиентах.

## 2. Что нужно сделать (по шагам, с точными значениями)

Все имена ниже уже прописаны в конфиге — менять их нельзя, иначе деплой не сойдётся.

| что | значение |
|---|---|
| имя воркера | `ccna-sync` |
| имя базы D1 | `ccna-sync` |
| привязка (binding) | `DB` |
| домен | `sync.maks.top` (зона `maks.top` уже в Cloudflare) |
| секреты в GitHub | `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID` |

### Шаг 1. Вход в Cloudflare

`https://dash.cloudflare.com` — **логин делает пользователь**. Дальше агент ведёт по
интерфейсу и показывает, куда нажимать.

### Шаг 2. База D1 с именем `ccna-sync`

Dashboard → **Storage & Databases → D1 SQL Database → Create**. Имя строго `ccna-sync`.
Регион: ближайший к пользователю (он в Австралии) или «автоматически».

Скопировать **Database ID** (UUID) — он понадобится на шаге 3 и он не секрет.

### Шаг 3. Вписать `database_id` в репозиторий

В `ccna-sync/wrangler.jsonc` сейчас стоит заглушка:

```jsonc
"database_id": "PASTE_DATABASE_ID_HERE"
```

Заменить на UUID из шага 2, закоммитить и запушить в `main`. Это обычная правка файла,
не секрет. Достаточно прислать UUID в чат — правку сделает агент.

### Шаг 4. Account ID

Dashboard → **Workers & Pages** (или из URL дашборда: `dash.cloudflare.com/<account_id>/…`).
Скопировать. Он нужен CI как секрет `CLOUDFLARE_ACCOUNT_ID` — не потому, что он тайна, а
потому что у токена может быть доступ к нескольким аккаунтам, и без него `wrangler`
не знает, в какой деплоить.

### Шаг 5. API-токен для CI

**My Profile → API Tokens → Create Token → Create Custom Token.** Права (имена точные,
как в интерфейсе Cloudflare):

| область | право | зачем |
|---|---|---|
| Account | **Workers Scripts: Edit** | публиковать воркер |
| Account | **D1: Edit** | применять миграции на боевой базе |
| Zone | **Workers Routes: Edit** для зоны `maks.top` | привязать `sync.maks.top` |

Шаблон «Edit Cloudflare Workers» тоже подходит, **но D1 в него может не входить** —
проверить список прав глазами в самом интерфейсе перед созданием и добавить `D1: Edit`,
если его нет. Не выдавать прав больше, чем в таблице: Global API Key не использовать
никогда.

Account Resources — только нужный аккаунт. Zone Resources — только `maks.top`.
TTL можно не ограничивать.

**Токен показывается один раз.** Не копировать его в чат — сразу шаг 6.

### Шаг 6. Секреты в GitHub

`https://github.com/NickelFace/ccna-trainer` → **Settings → Secrets and variables →
Actions → New repository secret**. Два секрета:

- `CLOUDFLARE_API_TOKEN` — токен из шага 5;
- `CLOUDFLARE_ACCOUNT_ID` — Account ID из шага 4.

Значения вставляет пользователь. Проверить только имена (побайтно) и что оба появились в
списке.

### Шаг 7. Первый деплой

Пуш из шага 3 запустит `.github/workflows/sync-deploy.yml`. Пока секретов не было,
воркфлоу гонял только тесты; теперь он ещё применит миграции на боевой базе и опубликует
воркер. Если пуш был раньше секретов — перезапустить: **Actions → Sync server → Run
workflow**.

### Шаг 8. Домен `sync.maks.top`

Домен уже объявлен в `wrangler.jsonc` как custom domain, поэтому при деплое с правом
`Workers Routes: Edit` Cloudflare привяжет его и создаст DNS-запись сам. Проверить:
**Workers & Pages → ccna-sync → Settings → Domains & Routes** — там должен быть
`sync.maks.top`. Если его нет (не хватило прав) — добавить кнопкой **Add → Custom
domain**, имя `sync.maks.top`.

### Шаг 9. Проверка

```bash
curl -s https://sync.maks.top/v1/health
```

Ожидается ровно `{"ok":true}`. Затем сквозная проверка настоящим ключом (ключ придумать
случайный, 32+ символа, `A-Za-z0-9_-`):

```bash
KEY=<случайный-ключ-32-символа>
curl -s -H "Authorization: Bearer $KEY" https://sync.maks.top/v1/state
curl -s -X PUT -H "Authorization: Bearer $KEY" -H 'content-type: application/json' \
     -d '{"rev":0,"blob":"hello"}' https://sync.maks.top/v1/state
curl -s -H "Authorization: Bearer $KEY" https://sync.maks.top/v1/state
```

Должно быть: `{"rev":0,"blob":null}` → `{"rev":1}` → `{"rev":1,"blob":"hello"}`.
Этот тестовый ключ потом никак не мешает — он просто одна строка в таблице.

## 3. Что вернуть в основной чат

1. `database_id` базы D1 (не секрет).
2. «Секреты `CLOUDFLARE_API_TOKEN` и `CLOUDFLARE_ACCOUNT_ID` добавлены» — без значений.
3. Результат `curl https://sync.maks.top/v1/health`.
4. Привязан ли домен автоматически или руками.
5. Тарифный план аккаунта (Free/Paid) — от этого зависят лимиты ниже.

---

## 4. Проверенные факты о лимитах (Free)

- Workers: **100 000 запросов в сутки**, 10 мс CPU на вызов, скрипт до 3 МБ.
- D1: **500 МБ на базу**, 10 баз, до 2 МБ на строку, SQL-запрос до 100 КБ.

Один пользователь с двумя устройствами — это единицы запросов в день и десятки килобайт
состояния. Платить не за что; blob в воркере ограничен 1 МБ на всякий случай.

---

## 5. Чего делать не нужно

- Не менять протокол, имена, домен и схему таблицы — под них написаны тесты и клиенты.
- Не трогать код клиентов (`ccna-exam-simulator/`, `ccna-mobile/`) — их синхронизация
  делается в основном чате следующим шагом.
- Не включать Access / WAF-правила / Rate limiting поверх `sync.maks.top` — воркер
  вызывается из приложения, лишний редирект на страницу входа его сломает.
- Не создавать KV, R2, Durable Objects, вторую базу или второй воркер.
- Не переносить зону `maks.top` и не менять её DNS-записи, кроме той, что Cloudflare
  создаёт сам под custom domain.

## 6. Быстрый путь мимо браузера (если пользователь захочет)

Всё, кроме секретов в GitHub, делается из терминала одним логином:

```bash
cd ccna-sync && npx wrangler login     # OAuth в браузере, пользователь подтверждает сам
npx wrangler d1 create ccna-sync       # печатает готовый блок с database_id
npx wrangler deploy                    # публикует и привязывает sync.maks.top
```

Тогда браузерная часть сводится к шагам 5–6 (токен и секреты) — они нужны, чтобы деплой
шёл из CI, а не только с этой машины.
