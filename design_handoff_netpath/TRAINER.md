# Экраны тренажёра — спецификация

Редизайн восьми существующих экранов веб-симулятора (`ccna-exam-simulator`). Макет: `Trainer Screens.dc.html`.

**Главное правило: ни одной новой функции.** Все экраны, кнопки, состояния и подписи уже реализованы в `assets/js/app.js`. Строки интерфейса взяты из таблицы `I18N.ru` дословно — не переписывать «по смыслу», иначе разъедется с EN-версией и с кодом. Числа взяты из `data/meta.json` и из скриншота владельца.

Приложение одноколоночное и работает на телефоне. Ширина колонки в макете — 880 px как эталон настольного вида; вся вёрстка обязана сжиматься в одну колонку без горизонтального скролла на 375 px.

## Технический контекст

Ванильный JS, без сборки, без фреймворка. Разметка собирается шаблонными строками прямо в `app.js`, стили — в `assets/css/styles.css`. Классы, на которые опирается существующий код и которые надо сохранить: `.wrap`, `.card`, `.btn`, `.btn.primary`, `.opt`, `.opt.sel/.correct/.wrong`, `.k`, `.chip`, `.chip.on`, `.c`, `.dbar`, `.track`, `.fill`, `.badges`, `.badge`, `.qnum`, `.qtext`, `.cli`, `.cli-wrap`, `.exp`, `.rationale`, `.ropt`, `.rhead`, `.tag`, `.verdict`, `.grid`, `.cell`, `.cell.cur/.answered/.flagged`, `.dd-wrap`, `.dd-col`, `.dd-bank`, `.dd-bucket`, `.dd-slot`, `.dd-item`, `.dd-item.sel/.dragging/.correct/.wrong`, `.timer`, `.timer.low`, `.stat`, `.nav`, `.spacer`, `.lang-switch`, `.lang-opt`.

**Работать в CSS, а не в JS.** Почти весь редизайн — переписывание `styles.css` под токены из `README.md`. Разметку в `app.js` менять только там, где ниже это указано явно. Ни одна функция не должна поменять поведение: `weightedPick`, `score`, `grade`, `ddCorrect`, `rationale` — не трогать.

## Токены

Те же, что на лендинге (`README.md` → Design Tokens), плюс одно добавление:

| Токен | Hex | Применение |
|---|---|---|
| red | `#B3453A` | **новый.** Только вердикт ошибки: `.verdict.bad`, `.opt.wrong`, `.ropt.bad`, бейдж «ошибка», провальный домен в отчёте |

Красного на лендинге нет и быть не должно — он приглушён специально, чтобы не выбиваться из палитры. Зелёный `#2E7D6F` — верный ответ, золото `#C9A24A` — текущая позиция, таймер, акцент.

Шрифты: те же три (Playfair Display / Manrope / Space Grotesk) плюс **JetBrains Mono** для CLI-блоков и вариантов-команд. Моноширинный обязателен: в банке варианты ответа часто являются командами Cisco (`ip route 10.2.2.2 255.255.255.255 …`), и в пропорциональном шрифте они читаются хуже. В продукте CLI уже настоящий выделяемый текст, а не скриншот — это надо сохранить.

## Общее правило хрома

**Экзамен тёмный, тренировка светлая.** Единственное структурное добавление ко всем экранам, и оно нулевой стоимости: в экзамене есть таймер и нет пояснений, в тренировке наоборот. Хром говорит о режиме до того, как пользователь прочитает подписи. Реализуется классом на корневом контейнере, не новой разметкой.

## 5a · Главная (`home()`)

Заголовок `CCNA 200-301`, строка статистики `home_stats`, примечание `home_verified_note`.

Три карточки режимов — `home_full_title/desc`, `home_custom_*`, `home_practice_*`. Первая выделена (тёмная, золотая кнопка): полный экзамен — основной сценарий. Две другие светлые с рамкой. Эмодзи-иконки (🎯 ⚙️ 📚) из текущей вёрстки **убрать**: они не в палитре и на разных платформах выглядят по-разному.

Секция `home_domains_title` — шесть полос. Номер домена (`1.0`, `2.0` …) отделён от названия: Space Grotesk, цвет `#8A8578`. Подпись справа — `home_domain_weight` («вес 20% · 378 вопр.»). Ширина заполнения = вес / максимальный вес (25% → 100%), **все полосы одного цвета `#16181D`** — второй цвет создавал бы ложное деление доменов на важные и второстепенные.

Реальные значения из `meta.json`:

| Домен | Вес | Вопросов | Ширина |
|---|---|---|---|
| 1.0 Network Fundamentals | 20% | 378 | 80% |
| 2.0 Network Access | 20% | 296 | 80% |
| 3.0 IP Connectivity | 25% | 244 | 100% |
| 4.0 IP Services | 10% | 159 | 40% |
| 5.0 Security Fundamentals | 15% | 173 | 40%→**40%** |
| 6.0 Automation and Programmability | 10% | 145 | 40% |

(Security 15% → 60%. Считать формулой, не вписывать руками.)

Ниже — примечание `home_dd_note` со ссылкой `home_sims_link` на лаб-симуляции, и футер `home_footer`.

## 5b · Свой экзамен (`cfg('exam')`)

Чипы доменов (`cfg_domains_label`) с счётчиком вопросов внутри чипа; выбранный — залитый `#16181D`, счётчик в нём золотой. Чипы типов (`cfg_types_label`): Текст 798, Со схемой 403, Drag & Drop 159.

`cfg_count_label` и `cfg_time_label` в текущем коде — `<select>`. **Заменить на сегментированные кнопки:** вариантов три-четыре, выпадающий список для такого набора — лишний клик и лишняя платформенная отрисовка. Значения ровно те, что в коде: количество 30 / **60** / 100, время 30 / **90** / 120 / без таймера (жирным — текущий default, сохранить).

Кнопки `nav_back` и `cfg_start_exam` («Старт →»). **Добавить счётчик** «Под фильтры подходит N вопросов» перед кнопкой старта: `domPool()` это число уже знает, а пользователь сейчас узнаёт о пустой выборке только через `alert('Нет вопросов под выбранные фильтры')`. Единственное изменение в JS на этом экране — вывести уже вычисляемое значение.

## 5h · Тренировка · настройка (`cfg('practice')`)

Отличия от 5b:

- Чипы типов включают **Симуляция 35** — рисуется пунктирной рамкой и приглушённым цветом, с подписью «не оцениваются, только читаются». В коде симуляции подмешиваются только в тренировке и `scorable()` для них возвращает false — визуальное отличие должно это отражать.
- Количество: 20 / 50 / 100 / все (default 20).
- Нет выбора времени — тренировка без таймера.
- Чип `cfg_shuffle` («перемешать») — включён по умолчанию, вынесен под заголовок «Порядок».
- Блок `cfg_jump_label` («Или сразу к вопросу по номеру») на тёплой подложке `#F4F0E8` с пояснением, что фильтры игнорируются. Placeholder `cfg_jump_placeholder` — «Введите любой номер вопроса: 1 – 1397». Максимум считает `maxQN()`, не хардкодить.
- Кнопка `cfg_start_practice` («Начать →»).

## 5c · Вопрос экзамена (`renderExam()`)

Тёмная полоса хрома: `✕` (подтверждение `exit_confirm`), прогресс-бар, счётчик `14/100`, таймер. Таймер — Space Grotesk, при `.low` (меньше 2 минут) окрашивается в `#B3453A`.

Бейджи (`qBadges`): домен (короткое имя, бирюзовый), `q_label` («Вопрос 412», Space Grotesk), `badge_exhibit` («СХЕМА»), `badge_choose` («ВЫБЕРИ 2», золотая рамка), `badge_disputed` («СПОРНЫЙ КЛЮЧ»).

Текст вопроса 20px/600. CLI-блок — тёмный терминальный, JetBrains Mono, с подписью команды сверху; длинные под `<details>`, как сейчас. Схемы (`.eximg`) — как есть, растровые кропы из дампа.

Варианты `.opt`: буква в кружке, текст. Выбранный — залитый `#16181D` с золотой буквой. Для вопросов «выбери 2» одновременно выбранных может быть несколько — это уже так работает.

Нижняя навигация: `nav_prev`, `nav_next`, `flag_off`/`flag_on` («☆ на потом» / «★ снять метку», золотая рамка когда включено), `nav_finish_exam` («Завершить», подтверждение `finish_confirm`).

**Сетка `.grid` остаётся под ответами**, как в коде, а не уезжает в сайдбар: на телефоне сайдбара нет, а сетка нужна в обоих видах одинаково. Состояния ячеек: `.answered` — залитая, `.flagged` — золотая рамка, `.cur` — залитая золотом с обводкой. **Добавить легенду** под сеткой («отвечено 11 · на потом 2 · не отвечено 87»): сейчас цвета ячеек ничем не подписаны.

## 5d · Drag & Drop (`ddMarkup()`, `wireDDExam()`)

Две колонки: `dd_elements` («Элементы») слева на тёплой подложке, `dd_categories` («Категории») справа. Элемент в банке — светлая карточка с моноширинным текстом; у первого лёгкий наклон `rotate(-1.2deg)` и тень — знак, что предмет перетаскиваемый.

Три состояния слота: пустой (`1px dashed rgba(22,24,29,.26)`), активный при наведении — `.over` (`1.5px dashed #C9A24A` + золотая подложка), заполненный (залитый `#16181D`).

Подпись «Лишние элементы остаются здесь» — дистракторы реально есть (`ddExpected` возвращает `null` для них), но сейчас об этом ничего не сказано.

Кнопка `dd_check` («Проверить») заблокирована, пока размещено меньше `ddNeeded(q)`. Рядом счётчик «Разложено 1 из 3» — берётся из тех же данных, что и `disabled`.

На мобильном работает тап: клик по элементу, потом по слоту. Выбранный элемент — `.dd-item.sel`, нужно заметное состояние выбора.

## 5e · Тренировка · разбор (`renderPractice()`, `rationale()`)

Светлый хром: `nav_exit` («✕ выход»), `practice_review_btn` («📋 Разбор ошибок»), поле перехода по номеру `№`, счётчик `7/20`, счёт `5✓ 2✗` (зелёный / красный).

После ответа варианты блокируются: неверный выбранный — красная рамка с крестиком в кружке, верный — зелёная с галочкой, остальные приглушены до `opacity: .5`.

Вердикт (`verdict_incorrect` + `key_inline`): «✗ Неверно · ключ: C» на красной подложке.

Разбор по вариантам (`.rationale`): по одному блоку на показанный вариант. Заголовок блока — буква, текст варианта, тег (`tag_incorrect` + `your_choice` → «✗ неверно · твой выбор»; `tag_correct` → «✓ верно»). Под заголовком — проза из `q.why[k]`, разбитая по предложениям (`expParts`), длинная под спойлером.

Какие блоки показывать — **не менять**, логика в `rationale()`: для вопроса с одним ответом при ошибке показываются выбранный и верный; при верном ответе только верный; для «выбери N» — все варианты.

Кнопка `copy_for_ai` («📋 Скопировать для ИИ») — **сохранить как полноценный элемент, не прятать.** Это самая своеобразная функция продукта: она собирает вопрос, варианты и ваш ответ в текст для ИИ-чата и намеренно не включает собственное пояснение, чтобы модель рассуждала с нуля.

В EN-режиме русская проза (`why`/`exp`) скрывается — остаётся структурный вердикт. Значит блок разбора должен корректно выглядеть **пустым**: только теги и ключ, без осиротевших заголовков.

## 5f · Результат (`finishExam()`, `renderResults()`)

Тёмная шапка: `results_title`, балл крупно (Space Grotesk 68px, золотой), `/ 1000`, примечание `scale_note` («шкала 300–1000 · порог 825»), бейдж `pass_badge`/`fail_badge`, строка `correct_pct`.

Балл — `300 + pct*700`, порог 825. Не пересчитывать и не округлять иначе, чем сейчас.

`by_domain` — шесть полос с фактическим `ok/tot` по домену. Цвет полосы по результату: ≥80% зелёный, 60–79% золотой, <60% красный. Это единственное место, где цвет полосы несёт смысл, — здесь он про результат, а не про важность домена.

Кнопки `nav_home` и `another_exam` («Ещё полный экзамен»).

## 5g · Разбор (`renderPracticeResults()`, `reviewItemHTML()`)

Заголовок `review_title`. Фильтр-чипы `filter_errors` / `filter_all` / `filter_correct` со счётчиками; активный залит. По умолчанию открыт на «Ошибки», если они есть (`S.reviewFilter`).

`copy_mistakes` («📋 Скопировать ошибки для ИИ») — справа в строке фильтров, показывается только когда ошибки есть.

Карточка вопроса: шапка с бейджем `badge_wrong`/`badge_ok`, доменом, номером и, если есть, «СПОРНЫЙ КЛЮЧ». Ниже текст, варианты со вердиктами, проза, `copy_for_ai_short` («📋 для ИИ»).

Для drag-and-drop вопросов пояснений нет (`with_why` покрывает только 1201 MC) — карточка должна честно это говорить, а не выглядеть недогруженной.

Пустые состояния: `no_errors` («Ошибок нет — можно выдохнуть 🎉»), `no_questions`, `no_correct`.

## Не рисовалось

Экраны существуют в продукте, но макетов нет — сделать по аналогии или запросить отдельно:

- **Лаб-симуляции** (`browseSims()`) — 35 справочных карточек, `sim_page_title`. Не оцениваются. Своя структура: `sim_guide_header` под спойлером, `sim_tasks_header` списком, ответ под `sim_show_answer`.
- **Итоги тренировки** (`renderPracticeResults()` шапка) — `practice_results_title`, `answered_pct`, `continue_practice`.
- **Переход к вопросу по номеру** (`pGoto()`) как отдельное состояние.

## Не входит в объём

- Логика: выборка, оценка, проверка drag-and-drop, выбор блоков разбора. Только оформление.
- Банк вопросов и пояснения. 194 drag-and-drop без `why` и 37 без `dd` — это работа по контенту, не по дизайну.
- Мобильное приложение (`ccna-mobile`) — **отдельный продукт**, а не обёртка: своя навигация, теория на 47 глав, SRS по Лейтнеру, прогноз готовности, тап вместо перетаскивания. Эти экраны к нему не относятся. Его редизайн — отдельный заход, и начинать его надо с чтения `ccna-mobile/src/app/` и `src/styles/tokens.css`.
- EN-перевод пояснений. Владелец и код сходятся: ~1200 объяснений существуют только на русском, в EN они скрываются намеренно.
