# План работ: NetPath

Что нужно сделать в кодовой базе. Спецификации значений — в `README.md` (бренд и лендинг) и `TRAINER.md` (экраны тренажёра); здесь только объём, порядок и критерии приёмки.

Репозиторий: [NickelFace/ccna-trainer](https://github.com/NickelFace/ccna-trainer), ветка `main`. Карта «экран → файл» — в `github.md`.

Три трека:

- **A — иконка Android-приложения** (`ccna-mobile`). Ни от чего не зависит, можно запускать первым.
- **B — лендинг** (`ccna-exam-simulator`, первый экран).
- **C — экраны тренажёра** (`ccna-exam-simulator`, восемь существующих экранов).

A независим полностью. B и C живут в одном проекте и делят `styles.css` — их лучше вести последовательно или хотя бы одним человеком, иначе токены разъедутся. Начинать с C: тренажёр — это сам продукт, лендинг лишь ведёт в него, и токены удобнее обкатать на экранах, где их больше.

Перед началом: прочитать `README.md` и `TRAINER.md` целиком, открыть `Trainer Screens.dc.html` и `Site Landing.dc.html` в браузере и пролистать. Все числа брать из документов, а не на глаз со скриншота.

## Трек A. Иконка Android-приложения

Утверждён вариант **2c** («ступени»). Геометрия — README → Brand.

Контекст: README мобильного приложения сам помечает текущую иконку как заглушку — «drawn from one vector glyph in the app palette, deliberately plain — replace `res/drawable/ic_launcher_foreground.xml` and `res/drawable/ic_splash.xml` if a real mark ever gets designed». Знак нарисован, замена ожидаема.

### A1. Векторные исходники
- [ ] Собрать SVG символа по таблице координат (viewBox `0 0 86 86`, три rect, rx 7).
- [ ] Три раскраски: на светлом (`#16181D`/`#16181D`/`#C9A24A`), на тёмном (`#F7F4EE`/`#F7F4EE`/`#C9A24A`), монохром (`#8A8578`).
- [ ] Проверить, что символ читается в 20 px — это минимальный допустимый размер.

**Приёмка:** SVG совпадает с макетом при наложении; ступени не сливаются в 20 px.

### A2. Adaptive icon для Android
- [ ] `foreground` — символ векторным drawable, отступ от края контейнера 20% (безопасная зона под любую маску).
- [ ] `background` — отдельный слой, сплошной `#16181D`. Не запекать фон в foreground: маска срежет силуэт.
- [ ] `monochrome` — слой для themed icons Android 13+: силуэт одним цветом, фон прозрачный.
- [ ] Проверить под тремя масками устройства: squircle, круг, скруглённый квадрат.

**Приёмка:** ни одна маска не срезает ступени; в круглой маске силуэт визуально по центру.

### A3. Растровые экспорты
- [ ] mdpi 48, hdpi 72, xhdpi 96, xxhdpi 144, xxxhdpi 192.
- [ ] Play Store — 512×512 PNG без прозрачности.
- [ ] Заменить старую иконку во всех плотностях, убрать неиспользуемые файлы.
- [ ] Заодно `res/drawable/ic_splash.xml` — сплэш рисуется из того же глифа, оставлять рядом старый знак нельзя.

**Приёмка:** на реальном устройстве иконка чёткая, без ореолов и артефактов ресайза; сплэш и иконка — один знак.

### A4. Название приложения
- [ ] Имя приложения и метки в манифесте — из одной переменной/ресурса, не литералом в разных местах. Владелец планирует смену имени.
- [ ] Убрать из названия и store-описания торговую марку экзамена как часть бренда; оставить только как дескриптор («тренажёр для 200-301»).

**Приёмка:** смена имени бренда — правка в одном ресурсном файле.

### A5. Осторожно с подписью сборки
- [ ] Ничего не менять в `android-release.yml` и в схеме версий (`BASE_VERSION` + номер запуска). Смена ключа подписи ломает установку поверх предыдущей версии и, из-за `allowBackup="false"`, уносит прогресс пользователя.
- [ ] Иконка на подпись не влияет — но если по ходу работы всплывёт соблазн что-то поправить в сборке, сначала спросить владельца.

**Приёмка:** сборка после замены иконки устанавливается поверх предыдущей без переустановки.

## Что НЕ входит в объём

Чтобы не было переизобретения:

- **Логику тренажёра — не трогать вообще.** `weightedPick`, `score`, `grade`, `ddCorrect`, `rationale`, выборка блоков разбора: поведение проверялось прогоном двух реализаций на 9732 результатах. Трек C — это `styles.css`, а не `app.js`.
- Банк вопросов и пояснения. 194 drag-and-drop без `why` и 37 без реконструированных `dd` — работа по контенту, не по дизайну.
- Мокапы внутри лендинга не превращать в живые компоненты. Это картинки-объяснения.
- Не добавлять секции, которых нет в макете: цены, отзывы, FAQ, блог. Владелец их не заказывал.
- Не переносить `support.js` и теги `<x-dc>` / `{{ … }}` в продакшн — это runtime прототипа.
- Не менять состав и веса шести доменов и порог 825: они соответствуют официальному плану экзамена.
- Не вводить React, сборку или фреймворк в веб-симулятор. Он намеренно без бэкенда и без сборки.
- **Мобильное приложение — отдельный продукт**, а не обёртка над веб-версией: своя навигация, теория на 47 глав, SRS по Лейтнеру, прогноз готовности, тап вместо перетаскивания. Из него в объёме только иконка (трек A). Редизайн его экранов — отдельный заход, начинать с `ccna-mobile/src/app/` и `src/styles/tokens.css`.
- Не менять схему подписи и версионирования релизов (`android-release.yml`): смена ключа уносит прогресс пользователей.

### C2. Экран вопроса и хром режима

**Приёмка:** режим виден до чтения подписей; «выбери 2» позволяет несколько выбранных; сетка читается без легенды в цвете и с ней в тексте.

### C3. Настройка попытки и главная
- [ ] Главная (5a): три карточки режимов, первая выделена; шесть полос доменов одного цвета, ширина = вес / max(вес). Эмодзи-иконки (🎯 ⚙️ 📚) убрать — не в палитре и разные на платформах.
- [ ] Свой экзамен (5b) и Тренировка (5h): `<select>` для количества и времени заменить сегментированными кнопками — вариантов три-четыре, выпадающий список тут лишний клик.
- [ ] Симуляции в чипах типов — пунктирная рамка и подпись «не оцениваются»: `scorable()` для них возвращает false, визуал должен это отражать.
- [ ] Добавить счётчик «Под фильтры подходит N вопросов». `domPool()` это число уже знает; сейчас пользователь узнаёт о пустой выборке только из `alert`. **Единственная правка в JS во всём треке.**
- [ ] Максимум в поле перехода по номеру — из `maxQN()`, не хардкод.

**Приёмка:** дефолты те же, что в коде (60/90 для экзамена, 20 + «перемешать» для тренировки); пустая выборка видна до нажатия «Старт».
