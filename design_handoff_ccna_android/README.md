# Handoff: CCNA Trainer — Android как отдельное приложение

## Overview
`NickelFace/ccna-trainer` — офлайн-симулятор экзамена Cisco CCNA 200-301: статический веб-апп
(`ccna-exam-simulator/index.html` + `assets/js/app.js` + `assets/css/styles.css`, банк 1395 вопросов
в `data/questions.json`), обёрнутый в Capacitor 7 в APK. Сейчас APK показывает ровно тот же веб-UI.

Задача: сделать **Android-приложение отдельным продуктом** со своим UX — таб-навигация, сохранение
прогресса, повторение ошибок по интервалам (SRS), статистика попыток, сопоставление тапом вместо
drag&drop, генератор готового промпта для ИИ. Веб-версия остаётся жить (та же логика, широкая
раскладка, клавиатура), но перестаёт диктовать мобильный интерфейс.

## About the Design Files
Файлы `Current UI.dc.html` и `Redesign.dc.html` в этом бандле — **дизайн-референсы, написанные в HTML**.
Это не продакшн-код: инлайн-стили, статичные данные, никакой логики. Их задача — точно показать
внешний вид, состав экранов и поведение.

Реализовывать нужно **в целевом окружении**, а не копировать эту разметку. Целевое окружение выбирается
по решению из `ANDROID_APP.md`: либо тот же ванильный JS/Capacitor-стек, что в репозитории (рекомендуется —
офлайн, без бандлера, один язык с существующим движком), либо нативный Kotlin/Compose, если решено
переписывать целиком. Существующая логика движка (`app.js`: выборка по весам доменов, скоринг 300–1000,
парсинг CLI-блоков, per-option rationale, drag-drop проверка) переиспользуется, а не пишется заново.

Как открыть: положить `support.js` рядом с `.dc.html` и открыть html в браузере. Ширина фреймов 390px,
высота 844px — типичный Android-экран.

- `Current UI.dc.html` — что есть сейчас (5 экранов, воссозданы 1:1 из styles.css/app.js). Референс
  «от чего уходим» + источник существующих токенов, если что-то нужно сохранить.
- `Redesign.dc.html` — анализ (9 находок с причинами в коде) + 9 макетов нового приложения.

## Fidelity
**High-fidelity.** Цвета, типографика, отступы, размеры тач-таргетов финальные — их надо повторить
точно. Незакрытые вопросы: иконки таб-бара (в макете вместо иконок текстовые лейблы с индикатором —
нужен реальный набор, Material Symbols), анимации переходов между экранами, тексты пустых состояний.

### Типографика
- **UI + текст вопросов:** Space Grotesk 400/500/600/700 (заменяет JetBrains Mono как основной шрифт).
- **Технический текст:** JetBrains Mono 400/500/700 — варианты ответа с командами/адресами/числами,

### Геометрия и отступы
- Скругления: экран-фрейм 28px · большие карточки 18–20px · карточки/варианты 14–16px ·
  кнопки 13px · чипы-элементы 10–11px · пилюли-фильтры 20px · бейджи 6–7px.
- Горизонтальный паддинг экрана: 20px. Вертикальные интервалы: 8 / 10 / 12 / 14 / 18 / 20 / 26px.
- Границы всегда 1px. Прогресс-полосы: 4px (в шапке), 7px (домены), 8–10px (готовность/шкала).
- **Тач-таргеты минимум 48dp** для главных действий и вариантов ответа, 44dp для второстепенных
  чипов. В старом UI варианты были 11px паддинга (~42px) — увеличено.
- Нижние панели: `padding: 12px 20px 26px` (26px — запас под жест-бар). Таб-бар: `10px 12px 22px`.
- Статус-бар в макете нарисован как 44px строка — в приложении это `env(safe-area-inset-top)`.

## Screens / Views

Все экраны — 390×844, `overflow:hidden`, фон `bg`. Липкая шапка сверху, липкая панель действий или
таб-бар снизу, скроллится только средняя область. Контент **никогда** не должен уходить под панели —
скролл-области нужен `padding-bottom` = высота панели.

### 1. Онбординг — шаг «дата экзамена» (`data-screen-label="Onboarding"`)
**Назначение:** от даты зависит дневная норма и приоритет плана.
**Layout:** лейбл `ШАГ 2 ИЗ 3` (12px mono, `primary`, letter-spacing 1px) → заголовок 27px в две
строки → пояснение 14.5px `text-2` → колонка из 4 карточек-радио (`gap:10px`) → подсказка в
пунктирной рамке (`#131720`, `1px dashed #2c3542`, radius 14px) → нижняя панель с «Назад» (текстовая
кнопка) и «Дальше» (primary, 15px паддинг, 30px по горизонтали).
**Карточка-вариант:** `padding:16px 18px`, radius 14px, слева заголовок 15.5px/500 + подпись 13px
`text-3`, справа круг 22px: невыбранный — `1.5px solid #3a4048`, выбранный — залит `primary-strong`
с белой галочкой; выбранная карточка получает фон `primary-bg` + границу `primary-strong`, подпись
становится `primary-text`.
**Копия:** «Через 2 недели / спринт · 60 вопросов в день» · «Через месяц / 30 вопросов в день ·
1 пробный в неделю» (выбран) · «Через 3 месяца и больше / спокойный темп · 15 вопросов в день» ·
«Даты пока нет / без нормы, только тренировка». Подсказка: «Точную дату можно указать в „Профиле“ —
тогда на главной появится обратный отсчёт и норма пересчитается сама.»
**Остальные шаги (не нарисованы, делать по этому же шаблону):** шаг 1 — уровень («первый раз /
готовился раньше / пересдача»), шаг 3 — язык интерфейса RU/EN (переносится из существующего
`setLang`, но уже как экран, а не пилюля в углу).

### 3. Вопрос (`data-screen-label="Question"`)
**Липкая шапка:** `✕` (22px, слева, 24px колонка) · центральный блок: строка 12px mono
(`62 / 100` слева, таймер `47:12` цветом `warn` справа, `white-space:nowrap`) + полоса 4px
(трек `#1a1e24`, заливка `primary`, ширина = % пройденного) · `☰` справа (открывает шторку с сеткой
вопросов и флагами). Низ шапки — `1px solid #1c2027`.
**Контент:** бейдж домена (12px/500 `primary-text`, фон `primary-bg`, граница `primary-border`,
radius 7px, `3px 9px`) + номер `№365` 12px mono `text-3` → текст вопроса 17px/1.5 → варианты
(`gap:8px`): `surface` + `border`, radius 14px, `padding:12px 16px`, min-height 48px, буква 13px
mono/700 в колонке 20px, текст варианта 15px mono; выбранный — `primary-bg` + `primary-strong`,
буква `primary`. Ниже строка второстепенных действий (`☆ Отложить`, `Aa Размер`, справа подсказка
`свайп → далее` 12px mono `text-disabled`).
**Нижняя панель:** кнопка «←» (`elev`, граница `border`, 48dp) + главная кнопка на всю оставшуюся
ширину: «Ответить» (тренировка) / «Дальше» (экзамен, отвечает сразу при выборе).
**Exhibit:** там, где у вопроса есть `img`, картинка ставится над текстом, `width:100%`,
radius 12px, тап — полноэкранный просмотр с зумом (в старом UI зума нет вообще). CLI-блок
(`q.cli`) — моно 12.5px на `surface-alt`, radius 12px, длинный сворачивается в «Показать вывод
команды (N стр.)».

### 4. Разбор ответа — шторка (`data-screen-label="Answer review"`)
Вопрос остаётся на экране с `opacity:.5`, варианты перекрашиваются: верный — `ok-bg`/`ok-border`,
ошибочный выбор — `err-bg`/`err-border`.
**Шторка:** `sheet` фон, `border-top 1px border`, `radius 24px 24px 0 0`, тень
`0 -18px 40px rgba(0,0,0,.5)`, ручка 36×4px `#2c3138` по центру.
Строка вердикта: «Неверно» 17px/600 `err` (или «Верно» `ok`) + «правильный ответ B · 90» 13.5px
`text-3` + справа бейдж SRS «повтор через 1 д.» (12px mono, граница `border`, radius 7px).
Далее блоки `surface-alt` radius 14px `padding:14px`: «Почему B» (заголовок 14px/600) и
«Почему не C» (заголовок цветом `err`) — текст 14px/1.6 `text-2`; затем моно-справка одной строкой
(«AD: connected 0 · static 1 · eBGP 20 · EIGRP 90 · OSPF 110 · RIP 120»).
Логика показа блоков — как в текущем `rationale()`: одиночный вопрос и верный ответ → только верный
вариант; ошибка → выбранный + верный; multi-select → все варианты.
**Действия:** «Разобрать с ИИ» (второстепенная синяя: `primary-bg`/`primary-border`/`primary-text`)
+ «Следующий →» (primary, flex:1).

### 5. Сопоставление вместо drag & drop (`data-screen-label="Match (drag-drop replacement)"`)
**Главное изменение UX.** Перетаскивания нет вообще.
**Шапка** как у вопроса, метрика справа — «4 из 6» (размещено).
**Контент:** текст задания 16px → подсказка «Тапни протокол, затем категорию. Тянуть ничего не
нужно.» 13px `text-3` → банк элементов: чипы во flex-wrap (`gap:8px`), 14px mono, radius 11px,
min-height 44px. Три состояния чипа: свободный (`surface`/`border`/`text-2`), **выбранный**
(`primary-bg`/`primary-strong`/`text`), размещённый (`surface-alt`, `1px dashed #2c3138`,
`text-disabled`, `line-through`).
**Категории:** карточки `surface` radius 16px `padding:14px 16px`, `gap:12px`. Заголовок 15px/600
mono. Когда элемент выбран, у каждой категории появляется подсказка справа «тапни, чтобы положить
SNMP» (12px `primary-text`) и граница подсвечивается `primary-strong`. Внутри — размещённые чипы
13.5px mono (`elev`, `#2c3138`) с «✕» для снятия; если есть свободные места — «2 места свободно»
13px `text-disabled`.
**Нижняя панель:** строка состояния «[SNMP] выбран — выбери категорию» + «Отменить» справа; ряд
кнопок «Сброс» (второстепенная) + «Проверить» (primary, активна только когда размещены все
обязательные элементы — счётчик `ddNeeded()` из текущего кода). Элементы-дистракторы остаются в
банке, это допустимый правильный ответ.

### 6. Готовый промпт для ИИ (`data-screen-label="AI prompt"`)
**Назначение:** заменить «📋 Скопировать для ИИ» (сейчас копируется только текст вопроса) на
полноценный промпт «объясни тему → разбери мою ошибку → закрепи».
**Layout:** шапка «← Разобрать с ИИ» (18px/600) → пояснение 13.5px `text-2` → лейбл `ЧТО ВКЛЮЧИТЬ`
→ чипы-переключатели во flex-wrap (13.5px, radius 20px, min-height 40px; включённый —
`primary-bg`/`primary-strong`/`text`, выключенный — `surface`/`border`/`text-3`): **Теория темы**,
**Разбор моей ошибки**, **5 вопросов на закрепление** (включены по умолчанию), Команды IOS,
Аналогия «на пальцах», Ответ на русском → превью промпта: `surface-alt`, radius 16px,
`padding:14px 15px`, моно 12.5px/1.75 `text-2`, `white-space:pre-wrap`, ограничено по высоте со
скроллом.
**Нижняя панель:** «Скопировать и открыть ИИ» (primary, на всю ширину) + ряд «Только скопировать»
и «Все ошибки домена».
**Шаблон промпта** (подставляются: уровень из онбординга, слабый домен из статистики, тема вопроса,
текст вопроса, выбранный и верный ответ; включённые чипы добавляют соответствующие пункты):
```
Ты преподаёшь CCNA 200-301. Я готовлюсь к экзамену, уровень — {уровень},
слабый домен {домен}.

Тема: {тема вопроса}.

Я ошибся в таком вопросе:
{текст вопроса}
Мой ответ: {буква} ({текст}). Правильный: {буква} ({текст}).

Сделай по порядку:
1. Объясни теорию темы с нуля, коротко и по делу, с таблицей {ключевой артефакт темы}.
2. Покажи, где именно ломается моя логика.
3. Дай 3 практических примера с выводом show-команд.
4. Задай мне 5 вопросов формата CCNA на эту тему и жди мои ответы, не показывай ключ сразу.
```
«Все ошибки домена» — тот же промпт, но с пачкой вопросов через `---` (переиспользовать
`copyMistakes()`), с шапкой «Ниже N вопросов, на которые я ответил неправильно…».
Копирование — системный clipboard; открытие ИИ — внешний intent на выбранное в настройках
приложение/URL (ChatGPT, Claude, Gemini). Промпт всегда доступен и без интернета — генерация
локальная, отправка ручная.

### 7. Результат экзамена (`data-screen-label="Results"`)
**Карточка счёта:** `surface`, radius 20px, `padding:16px`, центрирована. Балл 52px mono/700

## Interactions & Behavior
- **Навигация:** 4 таба (Главная / Учить / Экзамен / Прогресс), состояние каждого таба сохраняется.
  Экраны вопроса, разбора, сопоставления, настройки экзамена и промпта — модальные поверх табов
  (таб-бар скрыт). Системная кнопка/жест «назад» — шаг назад по стеку; во время экзамена —
  диалог «Выйти из экзамена? Прогресс сохранится».
- **Ответ в тренировке:** тап по варианту выделяет, «Ответить» проверяет → шторка разбора выезжает
  снизу (240ms, ease-out). Multi-select: выделяется несколько, кнопка активна от одного выбранного.
  В экзамене — выбор сразу сохраняется, разбор не показывается.
- **Свайп влево/вправо** — предыдущий/следующий вопрос (в вебе то же делают стрелки, как сейчас).
- **Сопоставление:** тап по элементу → он становится выбранным, у категорий появляется подсказка;
  тап по категории — элемент переезжает; тап по «✕» на размещённом — возврат в банк; «Отменить» —
  снять выделение. Никаких `dragstart`/`drop` (в текущем `wireDD` HTML5-drag на Android не работает).
- **Таймер** тикает раз в секунду, при <2 мин становится `err` и мигает (как сейчас `.timer.low`),
  всегда виден в липкой шапке. При истечении — автозавершение и переход к результату.
- **Прерывания:** любой ответ, размещение и тик таймера пишутся в стор; при возврате в приложение
  сессия восстанавливается с того же вопроса, оставшееся время пересчитывается от таймстемпа
  окончания. На главной — карточка «Продолжить».
- **Пустые состояния:** нет ошибок к повторению → карточка плана заменяется на «Всё повторено —
  возьми новый домен»; нет истории → график заменяется на приглашение пройти первый пробный.
- **Копирование промпта** — тост «Скопировано» (сейчас — подмена текста кнопки на 1.5с; оставить
  можно, но тост лучше).

## State Management
Персистентно (Preferences/SQLite, **не** только in-memory `S`, как сейчас):
- `profile`: `{ level, examDate, dailyGoal, lang, aiTarget }`
- `session`: `{ mode: 'exam'|'practice'|'srs'|'match', qs: number[], i, answers: {qn: {given|placement, ok?}}, flags: number[], endsAt, savedAt }` — одна активная, автосейв после каждого действия.
- `attempts[]`: `{ id, date, mode, scaled, pct, perDomain: {dom: {ok, tot}}, durationMs, answers }`
- `srs[qn]`: `{ box: 1..5, dueAt, lastResult, seenCount }` — Leitner: ошибка → box 1 (повтор через 1 день), верно → box+1 с интервалами 1 / 3 / 7 / 16 / 35 дней; в очередь дня попадают `dueAt <= now`, сортировка по box, лимит = дневная норма.
- `stats`: производные (готовность, прогноз балла, средн. время на вопрос, серия дней) — считать из `attempts` + `srs`, не хранить отдельно.
- `bookmarks[]`: отложенные вопросы (кнопка «☆ Отложить»).
- **Прогноз балла / готовность:** взвешенная по доменам Cisco доля верных за последние N=200 ответов, приведённая к шкале 300–1000 (как `scaled` в `finishExam`), с понижающим коэффициентом за непокрытые домены. Формулу зафиксировать в одном модуле и покрыть тестами.
- Существующая математика переиспользуется без изменений: `weightedPick()` (largest remainder по весам 20/20/25/10/15/10), `scaled = 300 + pct*700`, порог 825, `ddCorrect()`/`ddExpected()`.
