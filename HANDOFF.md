# HANDOFF — синхронизация двух чатов (exp для drag-and-drop)

Создано 2026-07-09. Координация двух параллельных работ по объяснениям dd-вопросов,
чтобы они не столкнулись по файлам и по времени. **Работы идут последовательно:
сначала Sonnet-чат (задача A), после него — Opus-чат (задача B).**

Общий контекст проекта — в `CLAUDE.md`, `ИНСТРУКЦИЯ.md`, `MEMORY.md`.

---

## Статус-доска (единственный источник правды по синхронизации)

Каждый чат обновляет свою строку по завершении. Opus стартует, только когда у
строки A стоит `DONE`.

| Полоса | Владелец | Файлы (пишет только сюда) | Задача | Статус |
|---|---|---|---|---|
| A | Sonnet-чат | `build/exp_parts/exp_batch_*.json` → `build/exp_data.json` | Написать `exp` для 157 dd, у которых есть данные | **DONE (157/157)** |
| B | Opus-чат | `build/dd_parts/*.json` → `build/dd_data.json`; `build/exp_parts/exp_dd37_*.json` → `build/exp_data.json` | Реконструировать настоящие drag-drop + их `exp` | **DONE (2/2: #545, #1289; dd_ready 159/194, with_exp 566). Остальные 35 — SIMULATION, не dd; см. открытый вопрос в MEMORY.md** |

Правила, гарантирующие отсутствие коллизий:

- **Полосы не пересекаются по номерам вопросов** (A = 157 номеров, B = 37 номеров),
  поэтому `exp_data.json` не перезаписывается — `merge_exp.py` делает `dict.update`.
- **Разные префиксы part-файлов**: A → `exp_batch_*`, B → `exp_dd37_*`.
- **`build_data.py` в один момент запускает только один чат** (работы последовательны — проблемы нет).
- Ни один чат не правит `data/questions.json` и `data/meta.json` руками (генерируются).

## Важно про формат объяснения (для обеих полос)

Объяснение dd-вопроса живёт в поле **`exp`** (одна строка текста), НЕ в `why`.
Приложение рендерит `q.exp` для `y==='dd'` (см. `assets/js/app.js`, функция
`rationale`). Формулировка «объяснения why для dd» в MEMORY была неточной.

Механизм: override-файл `build/exp_data.json` (`{"<n>": "текст", ...}`).
`build_data.py` подставляет его в `exp` при сборке. Наполняется через
`build/exp_parts/*.json` + `python3 merge_exp.py`. `merge_exp.py` не пропустит
номер, которого нет в банке, не-dd вопрос и пустую строку.

Для каждого вопроса всё нужное — в `data/questions.json` (только чтение):

cd ccna-exam-simulator
python3 -c "import json; Q={str(q['n']):q for q in json.load(open('data/questions.json'))}; \

**Что писать.** Одно связное объяснение на русском, 2–5 предложений: почему
элементы ложатся именно в эти корзины (ключевой признак каждого сопоставления).

фактический, как в существующих `why`/`exp`; без воды, без пересказа задания,
без выдуманных фактов. Обычный текст (перевод строки `\n` допустим).
