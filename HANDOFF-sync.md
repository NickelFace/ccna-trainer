## 1. Что есть сейчас (проверено по коду, не по памяти)

**Мобильное приложение `ccna-mobile/`** — состояние полное и уже сериализуемое.
`src/app/store.js` держит семь веток в Capacitor Preferences:

| ключ | что внутри |
|---|---|
| `profile` | уровень, дата экзамена, дневная норма, язык, шрифт, настройки уведомлений |
| `session` | текущая незаконченная сессия |
| `attempts[]` | завершённые попытки (см. форму ниже) |
| `bookmarks{}` | `{ on: { qn: ts }, off: { qn: ts } }` — закладка и её снятие с датами |
| `srs{}` | `qn → { box, dueAt, lastResult, seenCount }` |
| `activity{}` | `'YYYY-MM-DD' → { total, wrong, srs }` |
| `book{}` | `{ read, readOff, pos, open, last, scale }` — состояние чтения учебника |

`toBackup()/restore()` в том же файле — **готовый формат обмена `v:1`**, а
`src/app/backup.js` уже умеет отдавать его в системный share sheet. То есть формат
придумывать не нужно, он есть и обкатан.

Форма попытки (`finishSession` в `src/app/session.js:154`):

```js
{ id: `${startedAt}`, date, mode, preset, weighted, scaled, pct, ok, total,
  perDomain, durationMs, answers /* qn → ответ */, qs /* массив номеров */ }
```

Важно: `src/engine/stats.js` **ничего не хранит** — вся статистика пересчитывается из
`attempts`. Значит, попытка, записанная вебом, должна нести сырые `answers` + `qs`, а не
готовые цифры.

**Веб-симулятор `ccna-exam-simulator/`** — не хранит **ничего**. В
`assets/js/app.js:15` состояние живёт в глобальной `let S = {}` и умирает вместе со
вкладкой; в localStorage лежит только выбор языка. `finishExam()` (`app.js:1193`)
считает результат и кладёт его в `S.result`, никуда не записывая.

**Отсюда главное:** сегодня «перенести результат с сайта» невозможно не из-за отсутствия
бэкенда, а потому что **на сайте нечего переносить**. Хранилище в вебе — обязательный
шаг 0 при любом варианте.

Про балл — уточнение по факту кода (в плане было сказано неточно): формула в вебе
(`Math.round(300 + pct/100*700)` от уже округлённого процента) и в мобиле
(`toScaled` в `src/engine/score.js`) **совпадала до знака**. Расходились не числа, а
смысл: мобила помечает `weighted: false` для выборки, которая не взвешена по блюпринту,
и тогда балл не показывается как сравнимый, а веб такой пометки не имел вовсе.
Сделано: формула вынесена в `shared/score.js` (одна на двоих), веб проставляет
`weighted` — `true` только для полного экзамена.

**Хостинг сайта:** GitHub Pages (`.github/workflows/static.yml`), чистая статика —
бэкенд там поднять нельзя в принципе, он будет отдельным origin (значит CORS).
Репозиторий `NickelFace/ccna-trainer` (приватный), APK публикуется автоматически при
пуше в `main` (`android-release.yml`).

## 2. Шаг 0 — хранилище и формат `v:1` в вебе — СДЕЛАНО (2026-08-24)

Что появилось:

1. `ccna-exam-simulator/assets/js/store.js` — те же семь ключей `ccna.*` поверх
   `localStorage`, форма попытки поле в поле как в мобиле. Это ES-модуль (иначе не
   импортировать общий код), `app.js` остался классическим скриптом и берёт его через
   `window.Store` — как `window.NetPath` у лендинга. Всё через хендл `P()`: если модуль
   не загрузился, тренажёр работает как раньше, просто без памяти.
2. `finishExam()` и `finishPractice()` пишут `attempt`; у практики id один на прогон
   (разбор доступен по ходу, второй раз не должен плодить запись). Практика пишет
   **только отвеченные** вопросы: прогон может быть на весь банк, и неотвеченные — не
   ошибки, иначе статистика тем на обоих устройствах уедет в ноль.
3. Ответы по ходу пишут SRS и активность; ответы экзамена — разом в конце, только те,
   что реально даны.
4. Экран истории: последние три попытки на главной, полный список на своём экране,
   любая попытка открывается с разбором (`openAttempt`), можно удалить.
5. Выгрузка/загрузка файла `v:1` кнопками — **вариант A целиком**.

Критерий готовности выполнен и закреплён тестом: `ccna-mobile/tests/interop.test.js`
поднимает оба хранилища в node и проверяет обе стороны обмена — телефон восстанавливает
выгрузку браузера (и `topicStats`/`dueQueue`/`streakDays` её читают), браузер
восстанавливает выгрузку телефона, не теряя закладки и учебник и перегенерируя `deviceId`.

Чего в вебе намеренно нет: сохранения незаконченной сессии (§3, `session` не
синхронизируется) и экранов SRS/статистики — данные пишутся, показывает их телефон.

## 3. Слияние (`merge`) — СДЕЛАНО (2026-08-24)

`ccna-exam-simulator/assets/js/shared/merge.js`, тесты — `ccna-mobile/tests/merge.test.js`
(и сквозные, клиент против настоящего воркера, — `ccna-sync/test/roundtrip.test.js`).
Реализовано по плану ниже, с двумя отличиями от него:

- **`srs`** — поле `at` добавлено в `nextState`, вывод времени из `dueAt - intervalMs(box)`
  не используется: старые записи считаются как `at = 0` и проигрывают любой реальной
  оценке. Проще и честнее, чем восстанавливать время задним числом.
- **`bookmarks`** — тумбстоуны есть (сделано 2026-08-24, `shared/tset.js`): и добавление,
  и снятие датированы, побеждает более позднее. Форма ветки — `{ on: { qn: ts }, off: {...} }`;
  массив из старой сборки нормализуется в добавления с меткой 1, так что ничего не теряется.
  Тем же примитивом сделаны отметки «прочитано» в учебнике (`book.read` / `book.readOff`).

Ниже — исходный план, он же описание правил.



Сервер должен остаться тупым: хранит blob + номер ревизии. Вся логика — в **чистой
функции `merge(a, b)`**, в одном файле, с юнит-тестами рядом (как весь `engine/` в
мобиле, тесты гоняются `npm test` → `node --test`). Тогда сервер можно будет заменить
не трогая клиенты.

Правила по каждой ветке (продуманы под реальную форму данных, не абстрактно):

- **`attempts`** — append-only, объединение по `id`. Сейчас `id` = `startedAt` в
  миллисекундах; двум устройствам совпасть почти невозможно, но всё же добавить префикс
  устройства: `id: "<deviceId>-<startedAt>"`. Старые записи без префикса принимать как
  есть.
- **`srs[qn]`** — побеждает запись с более поздним последним ответом. **Времени ответа в
  структуре нет**, но оно выводится точно: `lastAnswer = dueAt - intervalMs(box)`
  (см. `nextState` в `src/engine/srs.js:16`). Лучше всё же добавить поле `at` в
  `nextState` и использовать выведенное значение только для старых записей.
  `seenCount` — брать максимум (сложение задвоило бы общую историю).
- **`activity`** — **не сливать счётчики.** Ни сумма, ни максимум не верны: сумма
  задваивает день, синхронизированный дважды, максимум теряет день, поделённый между
  устройствами. Правильно — переложить на счётчик по устройству:
  `activity[day][deviceId] = { total, wrong, srs }`, при чтении суммировать по
  устройствам. Слияние тогда тривиально и идемпотентно. Миграция: существующее плоское
  ведро приписать локальному `deviceId`.
- **`bookmarks`** — как есть (массив номеров) слить нельзя: снятие закладки неотличимо
  от «на том устройстве её ещё нет», и она воскреснет. Перевести в
  `{ qn: { on: bool, at: ts } }`, побеждает более позднее `at`. Читающий код (`isBookmarked`,
  `toggleBookmark` в `store.js:226`) поправить под новую форму.
- **`profile`, `book.pos`, `book.read`, `book.scale`** — last-write-wins. `profile`
  целиком по метке времени всего объекта; `book.pos`/`read` — поключево.
- **`session`** (незаконченный экзамен) — **не синхронизировать.** Тянуть недописанную
  сессию с таймером на другое устройство — это способ потерять экзамен, а не удобство.
  Либо исключить из синка совсем, либо отдельная явная кнопка «продолжить здесь».

`deviceId` — случайный id, генерируется один раз при первом запуске, лежит в `profile`.
В вебе это уже так (`web-xxxxxx`, перегенерируется при импорте чужой выгрузки, id попытки
= `<deviceId>-<startedAt>`); в мобиле пока нет — id попытки там всё ещё голый `startedAt`,
добавить вместе с `merge()`.

## 4. Бэкенд: Cloudflare Workers + D1 — СДЕЛАНО (2026-08-24)

Живёт в `ccna-sync/` (воркер, миграция, `wrangler.jsonc`, тесты), деплой —
`.github/workflows/sync-deploy.yml` при пуше в `main`. Адрес — **`sync.maks.top`**,
кастомный домен привязался при первом деплое. Аккаунт-часть (база, токен, секреты)
описана в `HANDOFF-cowork-cloudflare.md`.

Проверенные лимиты Free (в исходном плане было неверно «D1 free — 5 ГБ»): Workers —
100 000 запросов в сутки и 10 мс CPU на вызов; D1 — 500 МБ на базу, до 2 МБ на строку.
Блоб в воркере ограничен 1 МБ.

Ниже — исходный план протокола, он же его описание.

**Протокол** (оптимистичная блокировка, чтобы два устройства не затирали друг друга):

```
GET  /v1/state   → { rev, blob }
PUT  /v1/state   { rev, blob }  → 200 { rev: rev+1 } | 409 { rev, blob }
```

Клиент: `GET` → локальный `merge` → `PUT` с ожидаемой `rev`. На `409` — слить с тем, что
вернул сервер, и повторить. Сервер не знает про формат blob вообще.

**Авторизация без аккаунтов и паролей:** длинный случайный sync-key (32 байта,
base64url) генерируется на первом устройстве и вводится на втором вручную.
Сервер хранит строку по `SHA-256(key)`, никакой таблицы пользователей. Заголовок
`Authorization: Bearer <key>`. Для одного пользователя этого достаточно — это не
временный костыль.

**CORS — не забыть про два разных origin:**
- сайт на GitHub Pages (`https://nickelface.github.io` или свой домен);
- Android WebView: Capacitor 7 по умолчанию отдаёт `androidScheme: https`, то есть origin
  будет `https://localhost` (в `capacitor.config.json` схема не переопределена).
  **Проверить по фактическому заголовку `Origin` в логах воркера, а не поверить этому
  файлу.**

**Деплой:** `wrangler deploy` из GitHub Actions (`cloudflare/wrangler-action`, секрет
`CLOUDFLARE_API_TOKEN`). Отдельный воркфлоу, не трогать существующие `static.yml` и
`android-release.yml`.

**Если позже захочется классического стека для портфолио** (Go/FastAPI + Postgres +
Docker + миграции) — это меняется без правок в клиентах, протокол выше не завязан на
Cloudflare. Бесплатная площадка под такое — Oracle Cloud Always Free (ARM VM, без
ограничения по сроку). Cloudflare-вариант тоже портфолиен, но по-другому: serverless,
IaC через `wrangler.toml`, деплой из CI.

## 5. Где размещён общий код — РЕШЕНО

`ccna-exam-simulator/assets/js/shared/` — ESM-модули без DOM, localStorage и Capacitor:
`srs.js` (интервалы + переход состояния), `activity.js` (день, дневное ведро, обрезка),
`score.js` (шкала 300–1000), `backup.js` (формат `v:1`). Веб грузит их как модули,
`ccna-mobile/src/engine/*` реэкспортирует их относительным путём, esbuild вшивает в APK.
Копий нет, `npm test` в мобиле гоняет ровно тот код, который исполняет браузер.

Почему внутри `assets/`, а не в корне репозитория: это единственный каталог, который
отдают **и** локальный сервер (`--directory ccna-exam-simulator`), **и** Pages
(`static.yml` копирует `assets/`). Корневой `shared/` пришлось бы либо тащить в
`static.yml` и ломать локальные пути, либо менять корень дев-сервера.

`merge()` (§3) писать туда же — он нужен обоим клиентам.

Побочный эффект, уже учтён: APK теперь зависит от `assets/js/shared/**`, и этот путь
добавлен в триггеры `android-release.yml` — иначе правка общего правила не собрала бы
новый билд.

## 7. Грабли этого репозитория (стоили времени раньше)

- **Кэш веба.** При правке `assets/js/app.js` или `styles.css` — бампать `?v=N` в
  `index.html`, иначе браузер отдаёт старую версию даже после hard-reload. У
  `store.js?v=1` та же проблема, а его импорты (`shared/*.js`) версии не несут вовсе —
  при правке общего кода бампать версию модуля и помнить, что shared-файлы могут висеть
  в кэше до 10 минут.
- **Данные вопросов** не править в `data/questions.json` — только через override-файлы в
  `build/` + `python3 build_data.py` (к этой задаче не относится, но легко задеть).
- **Тесты мобилы**: `cd ccna-mobile && npm test` (`node --test`). Прогонять после каждого
  пункта, а не одним махом в конце.
- **Сборка APK**: `JAVA_HOME=/home/maks/tools/jdk21` обязателен, в PATH java нет.
  Пуш в `main` сам публикует релиз — проверять, что не улетело недоделанное.
- **Даты**: пользователь в Сиднее, в коде уже ловили баги от UTC-дат
  (`src/engine/localdate.js` существует именно поэтому). `dayKey` в `activity` — локальный
  день, при синхронизации между устройствами в разных зонах это надо не сломать.
- **Проверка на реальном устройстве.** Синк — ровно тот класс задач, где браузерная
  проверка врёт: WebView, CORS, фоновые паузы. Проверять на эмуляторе `ipcalc` через adb.
- **Английский в коде и README**, русский — в `README.ru.md` и в этом документе.
  Claude в соавторы коммитов не добавлять.
